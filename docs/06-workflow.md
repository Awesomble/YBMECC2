**2026-08-24 확정.** 조립과 자막은 사용자가 자기 프로그램으로 한다.

```
① 시나리오    사용자가 꼭지를 주면       →  나: cuts.json 작성
② 프롬프트    승인 격자·컷별 프롬프트     →  나: node prompts.mjs → PROMPTS.md
③ 배경        배경 + 화면 문자를 한 번에  →  사용자: image2 → <컷id>.png
④ 보정        글자가 틀린 컷만 수정      →  사용자: image2 편집 → <컷id>.final.png
⑤ 영상        완성 이미지로 i2v         →  사용자: 클링·옴니 → <컷id>.mp4
⑥ 목소리                               →  나: node tts.mjs → voice/
⑦ 조립·자막                            →  사용자: 자기 프로그램
```

**컷당 이미지 호출은 기본 1회다.** ③에서 배경과 화면 문자를 함께 뽑고,
**④는 글자가 틀렸을 때만 도는 수정 경로**다. 리터럴 문자열을 따옴표로 지정해 넘기므로
모델이 문구를 창작하지 않는다. image-to-video 는 **시작 이미지의 텍스트를 보존**하므로
③에서 들어간 글자가 영상 안에서 그대로 살아 움직인다.

> ⚠️ **한글 화면 문자는 아직 검증되지 않았다.** `prompts.mjs` 는 화면 문자를 **영문·숫자로만** 내고,
> 한글 설명은 자막이 담당하게 해 뒀다. 한글이 잘 나오는 게 확인되면 이 제약을 푼다.

**②에서 승인 격자를 먼저 통과시켜라.** 9칸 한 장으로 전체 룩을 보고 어긋난 컷을 잡는다.
③까지 다 뽑고 나서 발견하면 그만큼 다시 뽑아야 한다.

**⑦은 내가 하지 않는다.** 대신 붙이기 좋은 형태로 넘긴다.

| 산출물 | |
|---|---|
| `subtitles.srt` | 자막. 편집 프로그램이 그대로 읽는다 |
| `timeline.md` | 컷 순서·시작/끝·길이·파일 대조표. 나레이션 전문 포함 |
| `timeline.csv` | 같은 내용의 표 (스크립트·스프레드시트용) |
| `voice/<컷id>.m4a` | **컷별 음성** — 컷에 하나씩 얹으면 된다 |
| `voice/narration.m4a` | 통합본 — 컷 타임라인에 맞춰 무음 패딩이 들어 있다 |

```bash
node pipeline/export.mjs 1     # 자막·타임라인 갱신 → projects/00001-도메인구입/output/
pipeline/status.sh             # 모든 영상이 몇 단계인지
```

`status.sh` 는 **파일이 실제로 있는지 보고** 단계를 판정한다. 따로 표시할 게 없다.

## 화면 경로는 두 가지 — AI 실사 · 인포그래픽 카드

**2026-09-03 사용자 결정.** 수치·정책·비교가 본체인 정보형 주제는 AI 실사 대신
**인포그래픽 카드**로 간다. 첫 적용: `projects/00002-온누리적립/` (14컷 전부 카드).

```
나: cards/<컷id>.html 작성 (공통 시스템은 cards/style.css)
나: pipeline/cards.sh <p>  →  projects/<p>/assets/images/<컷id>.png (2160×3840, headless Chrome 2x)
사용자: 조립 때 팬·줌으로 움직임 부여 — i2v 불필요
```

| | AI 실사 | 인포그래픽 카드 |
|---|---|---|
| 어울리는 주제 | 감성·현장감 | 수치·정책·비교 |
| 한글 화면 문자 | ❌ 미검증 (영문·숫자만) | ✔ 자유, 오타 0 |
| 헤드라인 | 조립 때 얹는다 | **카드에 굽는다** (폰트 제어 가능) |
| 수정 비용 | 재생성 (호출 소모) | HTML 수정 → 재렌더 (무료·즉시) |
| i2v 크레딧 | 컷당 ≈ 8 | **0** |

⚠️ **2026-08-24 의 폐기는 유효하다** — 폐기된 것은 "HTML **애니메이션**을 영상으로 렌더"하던
방식이다 (임팩트 부족 + 렌더 파이프라인 유지비). 카드는 **정적 PNG 까지만** 만들고,
움직임은 조립(사용자)에서 넣는다. `render.mjs`·`lib/anim.js` 를 되살리는 게 아니다.

### AI 실사 경로 — 화면은 AI 가, 문구는 내가 정한다

**문구를 AI 가 지어내게 두지 않는다** — 정확한 문자열을
따옴표로 지정해 넘기고, 모델은 그걸 그리기만 한다.

```
③ 배경 + 화면 문자 (image2)   지정한 문자열을 그대로 그리게 한다
④ 보정 (image2 편집)          글자가 틀린 컷만. "이 글자만 고치고 나머지는 그대로"
⑤ AI 영상 (클링·옴니)          완성 이미지로 i2v — 텍스트가 보존된다
⑦ 자막                        조립 단계 (사용자)
```

| | |
|---|---|
| ③ 화면 문자 | **영문·숫자만.** 한글은 검증 전이라 자막에 맡긴다 |
| ④ 보정 | 편집 프롬프트가 **보존 목록을 매번 다시 적어** 드리프트를 막는다 |
| ⭐ 헤드라인 | 한글이라 **이미지에 넣지 않는다.** 상단 30%를 비워 두고 조립 때 얹는다 |
| ~~실제 상표·로고~~ | ~~가상 이름을 쓴다~~ → **폐기.** 주제 브랜드 CI 는 원본을 넣는다 (2026-09-07) |

`PROMPTS.md` 가 컷마다 **③ 이미지 프롬프트**와 **④ 보정 프롬프트**를 따로 낸다.

정보형 컷(가격표·업체명)은 **실제 화면 캡처**를 쓰면 신뢰도가 훨씬 높다.
그럴 컷은 `cuts.json` 의 `note` 에 그렇게 적어 둔다.

## ① 시나리오 — `cuts.json`

사용자가 꼭지 내용을 주면 **컷 단위로 쪼개서** 쓴다.

```json
{
  "id": "cut-01",
  "dur": 2.4,
  "say": "도메인, 첫해 가격만 보면 손해입니다.",
  "text": "첫해 가격만 보면 손해",
  "big": "2", "unit": "배 이상",
  "image": { "ko": { "scene": "...", "subject": "...", "detail": "...", "framing": "..." }, "en": {...} },
  "overlay": [ { "text": "$12/yr", "where": "좌측 카드 중앙", "style": "큰 숫자, 초록" } ],
  "video":   { "ko": { "camera": "...", "action": "...", "light": "..." }, "en": {...} }
}
```

| 필드 | |
|---|---|
| `dur` | **2~3초** (다른 문서 전부와 같은 기준). 여기서 정한 길이가 타임라인의 기준이다 |
| `say` | 나레이션 한 문장. 비우면 무음 컷 |
| `text` | 화면 자막. `say` 보다 짧게 줄여도 된다 |
| `big` / `unit` | 큰 수치. 조립할 때 강조로 쓴다 |

**지킬 것**

- **첫 컷이 훅이다.** 결과를 먼저 던진다. 인사·배경설명은 사망 선고 (`05-shorts.md`)
- **마지막 컷은 첫 컷과 같은 구도로.** 루프가 재시청을 만든다
- 전체 30~60초. 컷 12~25개 — **컷 하나 ≈ i2v 크레딧 8개**라는 걸 염두에 두고 정한다
- 수치·가격·정책은 **확인하고 쓴다.** `README.md` 의 "확인이 필요한 사실"에 근거를 남긴다

> ⚠️ **타이밍의 기준은 음성이 아니라 `dur` 다.**
> 그래서 음성을 다시 뽑아도 타임라인이 흔들리지 않는다.
> 말이 `dur` 보다 길면 `tts.mjs --measure` 가 어느 컷을 몇 초로 늘려야 하는지 알려준다.

## ② 프롬프트 → ③ 배경 · ④ 보정 · ⑤ 영상

```bash
node pipeline/prompts.mjs 1     # → projects/00001-도메인구입/output/PROMPTS.md · prompts/
```

`PROMPTS.md` 가 생긴다. 컷마다 **image2 프롬프트**와 **클링/옴니 프롬프트**가 복사하기 좋게
정리되고, 어떤 컷이 아직 비었는지 표시된다.

**사용자가 생성해서 넣는다.**

```
assets/images/cut-01.png        ③ 배경 + 화면 문자      ← image2
assets/images/cut-01.final.png  ④ 글자를 보정한 완성본 (필요한 컷만)
assets/clips/cut-01.mp4         ⑤ 영상 (선택)          ← 클링 / 옴니
```

**⑤ 는 최종 이미지를 넣는다.** 보정한 컷은 `.final.png`, 나머지는 `.png` 가 곧 최종본이다.

**클립은 전부 만들 필요 없다.** 영상 생성 쿼터가 병목이므로(`04-tools.md` §0),
**움직임이 꼭 필요한 컷만** 만든다. 나머지는 이미지를 그 컷 길이만큼 쓰면 된다.

### 프롬프트를 쓸 때

- **처음부터 9:16.** 16:9 를 크롭하면 구도가 망가진다
- **영상은 image-to-video 로.** text-to-video 는 컷마다 룩이 달라지고 쿼터도 빨리 마른다
- 구조: 주체와 동작 → 카메라 움직임 → 조명·분위기 → 스타일
- **③ 화면 문자는 리터럴 문자열을 따옴표로 지정한다.** 영문·숫자만 (한글은 검증 전)
- **컷 전체에 같은 룩**을 지정한다 (`cuts.json` 의 `style` 블록)

**작성법 상세는 `docs/08-prompting.md`** — 레거시 실사는 §2·§3. 현행 에셋 요청 형식은 공용 video ②.

## ⑥ 목소리

```bash
node pipeline/tts.mjs 1            # 컷별 (projects/…/voice/) + 통합본 (output/…/narration.m4a)
node pipeline/tts.mjs 1 --measure  # 길이만 재본다 (무료 say)
```

- `voice/<컷id>.m4a` — 컷별. 조립할 때 컷에 하나씩 얹는다
- `voice/narration.m4a` — 통합본. 컷 타임라인에 맞춰 무음이 들어 있다
- **말이 컷보다 길면 경고하고 몇 초가 필요한지 알려준다**
- 속도는 `cuts.json` 의 `voice.speed` (기본 1.5 = 50% 빠르게)

### 타입캐스트 한도

`voice.engine` 이 `typecast` 면 실제 음성이 생성된다. 한도가 있으므로 **사용자가 요청할 때만 돌린다.**
길이만 미리 재려면 `--measure` (무료 `say`).

**이미 있는 `voice/<컷id>.m4a` 는 재사용한다.** 대본을 고친 컷만 지우고 다시 돌려라 (전부 다시: `--force`).

## 에이전트가 지킬 것

- **단계를 건너뛰지 마라.** 꼭지를 못 받았으면 시나리오를 지어내지 않는다
- **⑥ 목소리는 사용자가 말할 때만** 만든다 (타입캐스트 한도)
- **⑦ 조립·자막은 내 일이 아니다.** 붙이기 좋은 형태로 넘기는 데까지다
- 내가 못 하는 일(이미지·영상 생성)은 **프롬프트를 만들어 넘긴다.** 만든 척하지 않는다
- **방식은 계속 바꿔 나간다.** 사용자가 조립해 보고 불편한 점을 말하면 산출물 형식을 고친다
