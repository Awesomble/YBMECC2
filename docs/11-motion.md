## 발화와 동작을 함께 설계한다

시간 정본과 명령은 공용 video/stages/3-voice.md를 따른다. 기본 원음 1.0배→단일 atempo 1.20배, cuts.json에는 표시 초를 기록한다. 실제 파일 길이·발화 끝·오프셋·읽을 시간을 함께 확인한다. 영상의 속도감은 음성 배속이나 트윈 개수로 대체되지 않는다.

핵심 발화 → 준비 동작 → 정점 → 읽을 결과 → 다음 상태를 같은 비트로 묶는다. 모든 행이 처음부터 완성된 표에 밑줄만 움직이면 빠른 음성에서도 포스터가 오래 머문다. 비교·교체·분해·결합·스케일 변화·피사체의 장면 간 이동으로 실제 정보 상태를 바꾼다. 저장용 요약 등 목적이 있는 정착은 충분히 읽힌다. 문장 간 무음·홀드 횟수·효과 크기에 일괄 상한을 두지 않는다.

무대 경계를 넘는 움직임을 기본 클리핑으로 자르지 않는다. 연출 레이어와 고정 락업/자막 레이어를 구분하되 발화와 의미는 연결한다. 사진의 컷아웃·깊이·전경 가림, 주제에 맞는 시그니처 동작을 선택한다.

## 자막과 BGM

자막 글자는 승인 대본을 실제 발화와 대조하고 어절 시간에 맞춘다. 숫자는 정확한 화면 표기로 쓴다. HyperFrames의 자막 시간은 표시 초이며 `hf-export.mjs`가 실제 자막 소스에서 SRT를 만든다. 레거시 Remotion의 subtitles.tsx 좌표·export 명령을 섞지 않는다. 좌표/최대 2줄은 docs/09-safezone.md §5를 따른다. 자막의 읽기를 흔드는 연출은 피하고 주연 그래픽에서 큰 동작을 만든다.

BGM은 사용 허용된 CC0 라이브러리에서 내용·분위기·실제 구간으로 고른다. 같은 곡 재사용, 루프, 도입부 사용을 일괄 금지하지 않는다. 발화를 가리지 않게 믹스하고 실제 출력에서 듣는다. 침묵·강약·종결/반복 연결은 대사의 의미에 맞춘다. 수치만으로 믹스 완성을 판정하지 않는다.

## 모션은 내용의 논증이다 — 컨셉 유지 + 매 영상 새 인터랙션 (2026-09-08 사용자 지시)

**같은 구도·동작 설계도를 복제하면 영상이 서로 닮는다.** 00002 와 00003 은 `frame.md` 가 `diff` 0줄로 동일했고
이징 `power*` 점유가 **92.2% / 69.5%** 였다. 사용자가 바로 알아챘다 — *"모션감이 비슷하네"*.
룰 라이브러리에 **48개**가 있는데 두 영상이 인용한 건 **1개**였다.

| 고정축 (채널 인식) | 가변축 (내용에 맞게 선택·발명) |
|---|---|
| 기본 폰트 · 좌상단 로고(`brand.json` `logo`) · 자막 스킨 · 정보 세이프존 · 60fps | 주연 소재 · 구도 · 동작의 물리 · 이음매 · 이징 |

**모션은 장식이 아니라 논증이다.** 컷마다 "이 문장이 무슨 일을 하는가"(비교·증감·분해·경로·반전·경고)
를 먼저 적고, **그 일의 물리**를 고른다. 룰 이름에서 시작하면 내용과 무관한 화려함이 된다.
그리고 **주제 브랜드가 실제로 하는 동작**(도장을 찍는다 / 층층이 쌓는다 / 주소를 친다)이
그 영상의 모션 언어다 — 거기서 끌어와야 "그 브랜드를 설명하는" 모션이 된다.
외부 레시피는 완성 화면이나 숫자 규격이 아니라 **왜 움직이는지, 무엇이 어떻게 변하는지, 어디서 읽히는지**를 검토하는 자료다. 시연의 전후 상태가 우리 발화와 다르면 쓰지 않는다. 채택한 동작은 실제 음성·세로 화면·다음 장면과 맞춰 다시 설계하고, 첫 화면·동작 정점·결과·이음매를 재생으로 확인한다.

## 동작은 이름·방향·시각으로 지시한다 — 외부 모션 사전 검토 (2026-10-15)

[모션 메뉴판](https://giting.kr/skills/motion-menu)(giting/motion-menu 0.4, MIT — AI 영상·모션 그래픽 용어 사전)을 우리 규칙과 대조해 **지시 형식과 헷갈리는 쌍 구분만** 가져왔다. 숫자 기본값·이징 고정·장면 목록은 아래 「가져오지 않은 것」의 이유로 뺐다.

**지시 형식:** STORYBOARD 행·워커 패킷의 동작은 **[대상] + [동작 이름] + [방향·경로] + [실측 발화 시각]** 으로 쓴다 — 예: 「가격표가 왼쪽에서 와이프 리빌, 정점 = `$9.40` 어절 4.12초」. 「역동적으로」「멋지게」「자연스럽게」 같은 형용사만으로 지시하지 않는다(같은 말이 워커마다 다른 동작이 된다). 시간은 사전의 기본값이 아니라 ③의 실측 어절에서 나온다.

| 헷갈리는 쌍 | 구분 | 우리 구현(HyperFrames·GSAP) |
|---|---|---|
| 줌 vs 달리(패럴랙스) | 줌은 화면 전체가 같은 비율로 커진다. 달리는 다가가며 가까운 층이 더 많이 움직인다 | 줌 = 장면 래퍼 `scale`. 달리 = 앞·중간·뒤 층의 `scale`·`y`를 서로 다른 양으로 |
| 팬 vs 트랙 | 팬은 모든 것이 같은 양만큼 밀린다. 트랙은 가까운 것이 더 많이 밀린다 | 팬 = 래퍼 `x`. 트랙 = 층별 `x` 차등 |
| 펀치 인(스냅 줌) vs 줌 | 펀치 인은 짧고 급하게 한 번 키워 박는다 | 짧은 `scale` + 정점에 효과음·자막 강조 |
| 크로스 디졸브 vs 아이리스 vs 와이프 vs 매치 컷 | 겹치며 바뀜 / 원이 열림 / 직선이 쓸고 감 / 앞 장면의 사물이 다음 장면의 같은 자리 사물로 이어짐 | `opacity` 교차 / `clip-path: circle()` / `clip-path: inset()` / 객체를 다음 장면 좌표로 넘김 — 정보가 이어지는 전환은 매치 컷이 먼저다(「발화와 동작」 — 피사체의 장면 간 이동) |
| 스태거 vs 오버래핑 액션 vs 팔로 스루 | 여러 개가 차례로 / 한 물체의 부분이 조금씩 늦게 출발 / 본체가 멈춘 뒤 끝부분이 늦게 멈춤 | `stagger` / 부분별 시작 시각 차 / 끝부분만 정착을 늦춤 |
| 안티시페이션(준비 동작) | 크게 움직이기 전 반대로 작게 움츠림 | 「발화와 동작을 함께 설계한다」의 준비 동작 — 정점이 어절에 오게 준비를 앞에 둔다 |
| 모션 블러 | 빠르게 지나는 구간에만 이동 방향 잔상 | 이동 구간에만 블러·셰이더 블러 층(`docs/14-hyperframes.md` §16), 정착 프레임에는 남기지 않는다 |

**가져오지 않은 것과 이유:**
- **역할별 이징 3개 고정(등장 out·이동 inOut·퇴장 in):** 이징을 한두 개로 고정하자 00002·00003의 `power*` 점유가 92%·70%가 됐고 사용자가 「모션감이 비슷하네」라고 했다(위 절). `inOut` 이동은 관통 컷 이음매에서 속도가 0이 된다(§이음매 정합 속도표 ✘). 이징은 가변축이다.
- **숫자 기본값(스태거 0.08초·안티시페이션 0.2초·스쿼시 20%·팔로 스루 0.15초):** 2026-09-16에 목표 수치를 전부 내린 이유와 같다 — 숫자를 입력으로 주면 그 숫자를 맞추고 화면이 죽는다. 시간은 실측 발화에서 정한다.
- **「오버슈트·바운스는 강조 한 곳에만」:** 취향 주장이고 횟수 상한이다(「punch 1회」 규격도 삭제했다). 쓰는 곳은 내용으로 정한다.
- **카운트업(「크게 세기」):** 숫자는 그 값을 말하는 어절에 최종값으로 박는다 — 굴러가는 카운터는 00072에서 사용자가 반려했다.
- **장면 7종 목록에서만 고르는 장면표:** 우리는 동작을 내용에서 발명한다(위 절·`resources/motion/README.md`). 목록에서 고르면 편마다 닮는다.
- **스플릿 스크린 기본·렌즈 플레어·데이터모시 같은 장식 효과:** 분할 패널은 2026-10-08 롱폼에서 반려됐고, 장식 효과는 정보 변화가 없다. 쓸 이유가 생기면 그 편에서 고른다(금지는 아니다).
- 사전의 CSS 데모는 참고 재현이지 우리 마크업이 아니다 — `resources/motion/`에는 우리 영상에서 검증된 조각만 넣는다.

## 에셋 키트 — 원자를 먼저 만들고 검증한 뒤 조립한다 (2026-09-08 사용자 지시)

**컷마다 요소를 즉석에서 만들지 마라.** 그렇게 하면 잘림·넘침이 컷마다 새로 생기고,
하나를 고쳐도 다른 컷에서 또 나온다. 실제로 킥커 뱃지의 한글 받침이 **전 컷에서** 깎이고 있었는데
감독도 QC 도 못 잡았다 (사용자가 눈으로 발견).

```
projects/<p>/motion/kit.tsx        이 영상이 쓰는 시각 원자 전부 — **정적**이다. 모션 없음
projects/<p>/motion/KitSheet.tsx   원자를 실제 배경·실제 크기로 한 장에 늘어놓은 검증 시트
COMP=Kit pipeline/render.sh <p> <출력> --sequence --image-format=png --frames=0-0
```

**원자를 쓸 때 지키는 규율** — 어기면 잘림이 돌아온다:

| | |
|---|---|
| 글자 마스크는 의도와 글리프 여유를 확인 | 과거 롤인 래퍼가 받침을 영구히 잘랐다. 의도한 리빌/마스크 자체의 금지는 아니다 |
| 글자에 `lineHeight` 명시 필수 | 기본 줄높이로는 한글 받침이 깎인다 |
| width/height 변경이 형제 배치에 주는 영향 확인 | flow 레이아웃은 밀릴 수 있다. 독립 배치·SVG attr 모프 등 의도된 변화는 허용 |
| 색은 역할로만 | 역할은 채널 팔레트(`docs/channel/05-brand-pipeline.md` §2)를 따른다 — 옛 ABM 골드·딥그린 예시는 쓰지 않는다 |
| 인라인 밑줄은 `inline-block` + `borderBottom` | inline span 의 `boxShadow` 밑줄은 **다음 줄 위로 샌다** |

**키트 시트가 실제로 잡은 것** (2026-09-08, 조립 전에):
킥커 받침 잘림 · `Cond` 밑줄이 다음 줄에 걸침 · 금액 두 개가 판 폭을 넘어 "원"이 잘림.
셋 다 렌더 한 장으로 드러났다. **이게 이 절차의 값어치다.**

⚠️ `qc.mjs` 의 **레이아웃** 항목이 위 규율 중 둘(잘림 위험·높이 애니메이션)을 소스에서 자동으로 잡는다.
키트 시트는 눈으로, `qc.mjs` 는 코드로 — 둘 다 있어야 한다.

**다음 영상에서는 이 키트를 참고해서 시작한다.** 원자 이름과 규격이 그대로 재사용된다.

## 사람 눈에 안 보이는 결함은 고치지 않는다 (2026-09-08 사용자 지시)

검사 도구는 **화면을 보지 못한다.** 수치가 틀렸다고 말해도, 그게 **재생 화면에서 보이지 않으면 결함이 아니다.**
도구가 낸 지적은 고치기 전에 반드시 이 질문을 먼저 통과시켜라 — **"이걸 사람이 볼 수 있나?"**

| 보이지 않는다 → 패스 | 보인다 → 고친다 |
|---|---|
| 뒤 레이어가 완전히 덮은 잔상 (불투명 배경 뒤의 op 1) | 첫 프레임이 비어 있다 · 문자가 잘린다 · 겹친다 |
| 에디터·스튜디오 편집 편의용 경고 (`id` 누락 등) | 화면 문자가 틀렸다 (수치·단위·표기) |
| 1프레임 게이팅 지연 · 1e-15 부동소수 경계 | 컷에서 움직임이 죽었다 (이탈 정지·진입 정지) |
| 셀렉터가 가리키는 요소만 틀린 검사 실패 | 색·대비가 읽히지 않는다 |

**판정은 눈으로 한다.** `node pipeline/hf-cli.mjs <p> snapshot`(실제 런타임 대조표) 또는 `pipeline/qc.mjs --frames` 로
프레임을 뽑아 **직접 보고** 나서 결정하라. 스크린샷 없이 "수치가 이러니 결함"이라고 적지 마라.

⚠️ 반대 방향의 함정도 같다 — **자체 제작한 임시 하네스의 스크린샷을 근거로 쓰지 마라.**
런타임(클립 게이팅·폰트·레이어)이 빠져 있어 실제와 다른 그림이 나온다. 2026-09-08 에
임시 하네스가 프레임 04·06 에 없는 결함을 만들어 냈다 — 실제 런타임에서는 정상이었다.

2026-09-08, 이음매 검증(`seam-gate`)·자막 싱크·컷 정렬을 전부 통과한 영상을 두고
사용자가 **"목소리만 빨라진 것 같은데? 모션하고 뭔가 안 맞아"** 라고 했다.
**컷은 어절에 맞았고(중앙값 +0.017초) 자막도 맞았다(중앙값 −0.02초).**
문제는 프레임이 **앞부분에 다 쏟아붓고 남은 시간을 얼어붙은 채 보내는 것**이었다 —

**정지 시간은 참고값이다.** 의도한 홀드를 수치로 반려하지 않는다. 의도하지 않은 빈 화면·내용 소실은 화면에서 확인해 고친다.

### 🔴 ②「빈 화면」은 ①로 안 잡힌다 — 다른 종류의 결함이다 (2026-09-08 추가)

0.7초에 한참 못 미쳐 ①을 통과하고, **컷 양쪽이 다 비면 이음매 화소 Δ 도 0 으로 나온다.**
어느 잣대로도 안 보이는 사각지대다.

들어오는 요소가 아직 안 들어온 자리다.

```
빈 화면  14.500 ~ 14.583   5프레임 (83ms)   ← 프레임 안쪽. 이월 요소 퇴장 ↔ 새 요소 진입 사이
         16.000            1프레임 (17ms)   ← 컷 경계
         18.250 ~ 18.333   5프레임 (83ms)   ← 컷 경계. 받기로 한 쪽이 autoAlpha 0 이었다
```

⚠️ **배경색을 상수로 박지 마라.** 렌더에 비네트·그라디언트가 들어가면 팔레트 값(`#14532D`)이

### ⚠️ 지표를 잘못 만들면 엉뚱한 데를 고치게 된다 (같은 날, 두 번 틀렸다)

처음에 **전체 화면의 평균 픽셀 변화량**으로 쟀다. 그랬더니 "64.9% 정지"라는 수치가 나왔고,
그걸 믿고 워커 9명을 보냈다. **틀린 수치였다.**

라벨 하나가 회색→잉크로 바뀌는 것처럼 **작은 면적의 변화는 전체 평균에 묻힌다.**
비트가 0.35초마다 촘촘히 깔린 프레임이 "89% 정지"로 나왔다.
반대로 진짜 죽은 프레임(1.5초 동안 흐린 헤어라인만 추가)은 순위에서 밀려 있었다.

**고친 지표**: 밝기가 12 이상 바뀐 픽셀이 40개 이상이면 "화면이 바뀌었다"로 센다.
**크기가 아니라 변화의 유무**가 기준이다. 그러자 죽은 구간이 정확히 짚였고 눈검사와 일치했다.

**교훈** — 수치를 근거로 대규모 작업을 시키기 전에 **그 수치가 눈검사와 일치하는지 먼저 확인하라.**
죽었다고 나온 구간과 살아 있다고 나온 구간의 양 끝 프레임을 나란히 놓고 보면 5분이면 검증된다.

   죽었다는 구간과 살아 있다는 구간의 양 끝 프레임을 나란히 놓으면 5분이면 검증된다

🔴 **정정 (2026-09-08).** 여기 처음엔 "0.05초 격자로 내림"이라고 적었는데 **틀렸다.**
부동소수점 때문에 3샘플마다 충돌하던 것을 격자로 오독한 것이다. 00003 세션이 잡아 줬고

```
--at 0.032  c1744b10…   프레임 0
--at 0.040  cd76372e…  ┐ 같은 해시 = 같은 프레임 1
--at 0.066  cd76372e…  ┘
--at 0.070  a8b5fd62…   프레임 2
```
0.05초 격자였다면 `(0.032,0.040)` 과 `(0.066,0.070)` 이 각각 같아야 하는데,
실제로는 **`(0.040,0.066)` 만** 같다. 1/30 예측 그대로다.

**파일명을 믿지 마라 — 두 군데가 어긋난다.**
`frame-02-at-0.066s.png` 에서 `0.066s` 는 **요청 시각**이고 `02` 는 **`--at` 목록의 순번**이다.

그래도 결론은 그대로다 — **스냅샷으로 모션 총량을 재지 마라.** 같은 프레임이 두 번 나오면
변화량 0 이 찍히는데 그건 정지 구간이 아니라 샘플링 아티팩트다.

`pipeline/motion-audit.mjs` 는 **렌더된 MP4 를 프레임 단위로** 읽으므로 이 함정에 안 걸린다.
모션 측정은 반드시 렌더된 영상으로 하라 — 스냅샷은 **눈검사 전용**이다.

## 이음매 정합 — 이징 경계 속도표 (GSAP 3.14.2 실측, 2026-09-08)

컷 이음매를 맞춘다는 건 **앞 컷의 `t=D` 속도**와 **뒤 컷의 `t=0` 속도**를 같게 만드는 일이다.
픽셀로 더듬지 말고 **트윈 파라미터로 해석해서 `D` 를 풀어라** — 픽셀은 검산이다 (00003 세션 실측).

### 🔴 `powerN` 은 `t^N` 이 아니라 **`t^(N+1)`** 이다

GSAP 규약이 `power1`=quad · `power2`=cubic · `power3`=quart · `power4`=quint 다.
렌더가 실제로 쓰는 3.14.2 로 역산해 확인했다 (`power4.in` 의 p(0.5)=0.03125 → 지수 5).

```
powerN.in   종단(t=D) 속도 = (N+1)·d/D
powerN.out  진입(t=0) 속도 = (N+1)·d/D
```

⚠️ **N 으로 잘못 쓰면 차수가 같은 이음매에서는 오차가 상쇄되어 안 드러난다.**
`power4.in → power4.out` 은 `4=4` 로 풀든 `5=5` 로 풀든 같은 `D` 가 나온다.
**차수가 다를 때만 어긋난다** — `power3.in → power4.out` 은 실제로 **6.7%**,
`power2.in → power4.out` 은 **20%** 벌어진다. 조용히 통과하다가 특정 이음매에서만 터진다.

### 전체 표 (d=이동거리, D=지속시간)

| 이징 | t=0 속도 | t=D 속도 | 이음매에 쓸 수 있나 |
|---|---|---|---|
| `none` | 1.000·d/D | 1.000·d/D | ✔ 가장 단순 |
| `power1.in` / `.out` | 0 / **2.000** | **2.000** / 0 | ✔ |
| `power2.in` / `.out` | 0 / **3.000** | **3.000** / 0 | ✔ |
| `power3.in` / `.out` | 0 / **4.000** | **4.000** / 0 | ✔ |
| `power4.in` / `.out` | 0 / **5.000** | **5.000** / 0 | ✔ |
| `powerN.inOut` | 0 | 0 | 정지→정지. 관통 컷엔 부적합 |
| `sine.out` | 1.571·d/D | 0 | ✔ |
| `sine.inOut` | 0 | 0 | 정지→정지 |
| `expo.out` | 6.931·d/D | ≈0 | ✔ 유한 |
| `back.out(1.7)` | 4.700·d/D | ≈0 | ✔ 유한 |
| **`circ.out`** | **4472·d/D** | 0 | 수직 접선 — 단순 속도 맞춤 계산을 그대로 적용하지 않는다 |
| **`elastic.out(1,.55)`** | 6.931·d/D | **4057·d/D** | 경계의 진동 상태를 실제 샘플로 확인한다 |

위 수치는 특정 파라미터·표본 위치에서 구한 참고값이다. `circ.out`·`elastic.out` 자체를 경계에서 금지하지 않는다. 연속성이 필요하면 이징의 실제 구간과 속도를 확인하거나 전환의 의도에 맞게 연결한다. `pipeline/motion-signature.mjs menu` 의 이징 서명표가 이 값을 같이 출력한다.
