# 비용 절감 — 무엇을 바꿨고, 나빠지면 어떻게 되돌리나 (2026-09-09)

**품질을 깎지 않는 것만 골라 넣었다.** 각 항목에 **되돌리는 명령**과 **되돌려야 할 신호**를 함께 적는다.
품질이 나빠졌다고 느껴지면 추측하지 말고 **아래 계기판을 먼저 재고**, 어느 항목이 원인인지 짚어 되돌려라.

**입력이 1% 다. 모델 단가를 만져도 거기선 안 나온다.**

⇒ 순서: ① `/fast` 끄기 ② 보고는 결론·위치·미검증만 짧게 ③ 영상마다 세션 끊기 ④ 모델 내리기(마지막)

쓰는 자리: **사용자**가 판단이 무거운 요청(② 훅·구조·에셋 경로와 3D 비교 판정, ⑤ 판정 이견, 원인 분석·가이드 개정)에 키워드를 붙인다. **공용 video SKILL.md 본문에는 넣지 않는다**(수십 턴 작업에 매번 발동, 문서도 one-off 용도로 설명). 역할 에이전트 깊이는 정의 파일 `effort:`로 정하고 프롬프트 속 키워드로 대신하지 않는다. Codex는 `~/.codex/config.toml`의 xhigh가 전역이고, 이미지 생성(`asset-prompts`·`bundle-widen`)은 `gpt-6.1-sol`·xhigh로 고정한다(2026-10-08). 교차검증은 2026-10-02부터 Codex를 쓰지 않는다.

### 그런데 44분 중 상당분이 **내 실수로 생긴 왕복**이었다

사용자가 **세 번** 지적해야 했다 — 로고·폰트 실종 · 모션 이동 0px · 글자 위계 역전.

## ① 지속 요소를 루트 트랙으로 — `pipeline/root-lockup.mjs`

같은 요소를 10개 프레임이 각자 그리면 이음매마다 앞 프레임의 기하를 손으로 복제해야 한다.
루트에 두면 **0px 일치가 측정 결과가 아니라 전제**가 된다.

**검증** (추정이 아니라 렌더로): v10 을 구워 v9 과 비교 —
전체 PSNR **52.78dB** · 락업 밴드 **52.30dB** (h264 잡음 바닥 45dB보다 높다) ·
게이트 동일 통과 · 락업 밴드 눈검사 동일.

```bash
node pipeline/root-lockup.mjs <p> --revert     # 되돌리기 (프레임 바이트 단위 복원 · 검증됨)
```

**되돌려야 할 신호**: 락업이 프레임마다 다르게 움직여야 하는 연출이 생겼을 때.
이 도구는 락업을 **전 구간 정지**로 만든다. 00003 은 원래 편차가 ±2px(안티에일리어싱)라 무영향이었다 —
**새 영상에서 먼저 재라**: 락업 밴드가 3px 이상 움직이면 그 모션이 사라진다.

⚠️ 조립을 다시 하면 `index.html` 이 재생성되므로 **조립 뒤에 다시 돌려야** 한다.

## ③ 렌더 게이트 — `pipeline/render-gate.sh`

소스 최신성 + lint + 모션·빈화면 + 이음매를 **8초에** 한 번에 돌린다.

00003 은 **빈 화면 결함이 v1 부터 있었는데 v8 까지 살아남아 사용자에게 한 번 나갔다.**
lint 는 v9 직전에야 처음 돌렸고, 그때 `.frame-solo.html` 을 잡았다 —
그게 없었으면 진입점이 둘이 되어 오디오가 겹친 영상을 납품할 뻔했다.

**판정을 갈라 놨다** — 이게 이 도구의 핵심이다:

| 검사 | 판정 |
|---|---|
| 소스 최신성 · lint · **빈 화면** | **하드 실패** (거짓 양성 없음) |
| 0.7초+ 정지 | **경고만.** 60fps 에서 얇은 선이 자라는 모션을 못 본다 — 눈으로 대조 |
| 이음매 | **참고만.** 🔴 는 「봐야 할 곳」이지 합불이 아니다 |

🔴 **정지 구간으로 게이트를 떨구면 사람이 게이트를 무시하게 된다.** 그래서 갈랐다.
반증 확인: v9 → exit 0 · v7(빈 화면 11개) → 하드 실패.

```bash
rm pipeline/render-gate.sh   # 되돌리기 (구성 도구는 각각 그대로 남는다)
```

**되돌려야 할 신호**: 게이트가 멀쩡한 렌더를 반복해 떨굴 때. 그때는 **지우지 말고
어느 검사가 거짓 양성인지 찾아 그 검사를 경고로 내려라** — 게이트 자체를 버리면 v1~v8 이 반복된다.

## ④ 보고 스키마 — 긴 근거는 파일로

보고 63건 × 중앙값 3,502자가 **영구히** 메인 컨텍스트에 쌓여 74K → 721K 로 부풀었다.
수치는 그대로 받고 결론·위치·미검증만 짧게 받는다. 별도 인계/보고 파일은 만들지 않는다 (`worker-brief.md` ③).

**되돌려야 할 신호**: 워커가 판단 근거를 못 전달해 팀리드가 잘못 판정하기 시작하면.
그때는 스키마를 버리지 말고 **`판정` 항목을 늘려라** — 00003 에서 값진 발견은 전부
「수치 + 그 수치를 어떻게 얻었나」였지 산문 자체가 아니었다.

## ⑤ 워커·감독 종료 규칙

- 워커: **편집 없이 측정만 이어지면 스스로 종료** (`worker-brief.md` ④-5)
- 감독: **동결 선언 뒤 1회만** 호출 (`stages/5-director.md`)

00003 에서 한 워커가 파일 확정 뒤 **143분(가동의 65%)** 을 측정 논쟁으로만 돌았고,
감독은 옛 판을 한 번 심사했다.

🔴 **정직하게 적어 둔다 — 그 143분이 `powerN` 발견을 만들었다.**
그 지식은 이제 `docs/02-pitfalls.md` 와 `worker-brief.md` 에 있으니 다시 살 필요가 없다.
**이 절감은 지식을 이미 지불했기 때문에 가능한 것이지 처음부터 공짜였던 게 아니다.**

**되돌려야 할 신호**: 새로운 종류의 결함이 나왔는데 워커가 원인을 못 찾고 종료할 때.
그때는 **그 프레임에 한해** 종료 규칙을 풀어라 — 전면 해제가 아니다.

## 미결 — 아직 안 돌린 실험

**단일 에이전트 대조군** (`.claude/skills/video/SKILL.md`). 10명 팬아웃이 정말 필요한지
게이트로 판정한다. 서브에이전트가 과금 입력의 **88%** 라 여기가 가장 큰 미지수다.
외부 사례(2026-09-08 공개 영상, 단일 Codex 에이전트로 4~11분)가 근거지만
그쪽은 렌더러를 밝히지 않았고 기획 단계를 건너뛰었다 — **수치가 아니라 가설로만 쓴다.**

## 되돌리기 전에 — 계기판부터

```bash
pipeline/render-gate.sh <p>              # 빈 화면·정지·lint·소스 최신성·이음매
node pipeline/seam-scan.mjs <p>          # 이음매만
```

「품질이 나빠진 것 같다」는 느낌으로 되돌리지 마라. **위 기준선과 대조하고,
프레임을 뽑아 눈으로 본 뒤** 어느 항목이 원인인지 짚어라.
00003 에서 지표를 세 번 틀렸고 그때마다 엉뚱한 곳을 고쳤다 (`docs/02-pitfalls.md`).

## 하지 않기로 한 것 — 품질을 깎는다

| | 왜 |
|---|---|
| **워커 10 → 6 감축** | 프레임 하나 = 에이전트 하나가 이 품질을 만들었다. 묶으면 프레임당 주의가 줄어든다 |
| **측정 줄이기** | 측정이 결함을 찾았다. 줄일 것은 측정이 아니라 **중복 측정과 자 불일치**다 |
| **렌더 횟수 줄이기** | 회당 35초다. 비용이 아니다 |
