## 0. 우리가 실제로 가진 것 (2026-08-23)

**아래 §2 의 비용 비교보다 이 절이 우선한다.** §2 는 "무엇을 살 수 있나"를 정리한 것이고,
이 절은 **"지금 무엇을 쓸 수 있나"** 다. 설계는 여기서 출발해야 한다.

| 자산 | 강점 | 제약 |
|---|---|---|
| **GPT Plus** | 이미지 생성 **일관성이 좋다** (실사용 확인) | 영상 생성은 기대하지 않는다 |
| **Google 비즈니스 계정** | Gemini 계열 기본 사용 | **쿼터가 작다.** Veo 를 마음껏 못 쓴다 |
| **Kling** | 영상 생성 | **소량.** 희소 자원으로 취급 |
| **Claude Max 20x** | 코드·대본·자동화 | 넉넉하다 |
| **클라우드플레어 Browser Rendering** | **웹 판독** — JS 페이지를 마크다운으로 (`pipeline/cf-crawl.mjs`) | 무료 **브라우저 600초/일** = 렌더 약 40쪽 |

### 여기서 나오는 결론

**영상 생성 쿼터가 파이프라인 처리량 그 자체다.**

```
정지 에셋   GPT Image      ← 배경·화면 문자·아이콘·썸네일. 일관성이 강점
움직이는 컷 Kling / Veo    ← i2v. 여기가 병목이다
대본·자동화 Claude Max
```

> ⚠️ **2026-09-03 정정.** 이 자리에 *"코드 렌더가 본체이고 AI 영상이 양념"* 이라고 적혀 있었다.
> **그 코드는 저장소에 없다.** HTML 방식을 폐기하면서 `render.mjs`·`lib/anim.js`·`build*.sh` 가
> 함께 삭제됐는데 문서만 남아 있었다. "정지 이미지를 코드로 움직인다"는 전술도 같이 사라졌다.
> **움직여야 하는 컷은 전부 i2v 를 거친다.**

### 주력 전술 — image-to-video 로 일관성을 잡는다

**GPT Image 의 강점이 일관성이고, Kling·Veo 는 첫 프레임을 주면 그 톤을 유지한다.** 둘을 붙인다.

```
GPT Image 로 완성 이미지 생성  →  Kling/Veo 에 넣어 image-to-video (5~6초)
                               →  assets/clips/<컷id>.mp4  →  사용자가 조립
```

**text-to-video 로 매번 새로 뽑으면 컷마다 룩이 달라지고 쿼터도 빨리 마른다.**
처음부터 **9:16 으로 생성**할 것 — 16:9 를 나중에 크롭하면 구도가 망가진다. 상세는 `05-shorts.md` §4.

### 쿼터를 아끼는 유일한 수단은 컷 수다

```
15컷 × 5초 i2v ≈ 120크레딧(첫 패스)  →  재시도 3~5배 반영 시 360~600크레딧
```

**컷 하나를 늘리는 건 크레딧 8개를 쓰는 결정이다.** 시나리오 단계에서 계산해라.
정지로 충분한 컷은 클립을 만들지 않는다 — 조립할 때 사용자가 팬·줌을 넣으면 된다.

**승인 게이트를 먼저 통과시켜라.** 9칸 격자 한 장으로 전체 레이아웃을 확인하고
어긋난 컷을 이미지 단계에서 고친 뒤 i2v 로 넘긴다. `prompts.mjs` 가 이 프롬프트를 함께 낸다.
격자는 **승인용 증거이지 자산이 아니다** — 칸당 340~680px 이라 그대로 쓰면 안 된다.

### ⚠️ 해상도 천장

생성 이미지는 보통 **1024~2048px** 이고, 세로 숏츠 출력은 **1080×1920** 이다.

```
표시 픽셀 = 출력 크기 × 확대 배율   →   소스 픽셀보다 작아야 한다
1080 × 1.15(완만한 줌) ≈ 1,250px
```

2048px 생성물이면 여유가 있다. **1024px 을 전체화면 배경으로 쓰면 그때부터 뭉개진다.**
자산 규칙은 `resources/README.md`.

## 1. 편집 앱 자동화 — 되는 것과 안 되는 것

```
다빈치 리졸브  >>  애프터이펙트  >>  캡컷  >>  파이널컷  >>  모션
   Python API     ExtendScript    draft JSON   FCPXML만    API 없음
   (Studio $295)     (구독)        (무료)      (구독)      (불가)
```

| 앱 | 자동화 수단 | 한계 |
|---|---|---|
| **다빈치 리졸브** | **공식 Python API** · MCP 서버 다수(★2,241) | **외부 스크립팅은 Studio($295) 전용.** 무료판은 앱 내 메뉴에서 사람이 실행하는 브릿지만 |
| **애프터이펙트** | **ExtendScript** (정식 API) · MCP 서버 다수 | 구독 필요. **앱이 떠 있어야 함** (헤드리스 불가) |
| **캡컷** | draft JSON 파일 직접 생성/수정 (`pyJianYingDraft` 등) | **렌더/내보내기를 사람이 눌러야 함.** 자동화가 마지막에 끊긴다 |
| **파이널컷** | **FCPXML 생성만** (`fcp-mcp` 94툴 존재) | 앱 조종 불가. **화면에 뭘 그릴지는 결국 Motion 에서 사람이 만들어야 함** |
| **모션** | **없음** (`NSAppleScriptEnabled=false`, sdef 없음) | 시도하지 말 것 |

**실제로 확인한 것**: 파이널컷은 FCPXML 을 생성해 임포트하는 데까지 성공했다.
이벤트·프로젝트·자막·마커가 정확히 들어갔다. **하지만 그 뒤가 전부 GUI 수작업이라 폐기했다.**
`fcp-mcp` README 도 스스로 *"not a claim of complete autonomous Final Cut Pro control"* 이라고 적어뒀다.

**결론**: 편집 앱을 **자동화**할 이유가 없다. 마지막에 반드시 사람 손이 들어가서 자동화가 끊긴다.

⚠️ 여기 *"헤드리스로 MP4 까지 무인으로 간다"* 고 적혀 있었으나 **지금은 아니다.**
조립·자막은 사용자가 자기 프로그램으로 한다(`06-workflow.md` ⑦). 우리는 `export.mjs` 가 내는
`subtitles.srt` + `timeline.md` + `voice/` 까지만 책임진다.

**리졸브가 값어치를 하는 시점**은 따로 있다 — 실사 촬영분이 많아지고 여러 클립의 색을 통일해야 할 때.
그때는 $295 가 아깝지 않다.

### 파이널컷 AI 로드맵 (참고)

2026-06 Apple Creator Studio 업데이트로 FCP 에 **Generate Captions · Edit Detection · Auto Mask ·
Match Color 개선 · Pixelmator Pro 연동**이 들어왔다. 전부 **앱 안의 기능**이다.

**Apple 이 외부 스크립팅 API 를 열겠다는 발표나 로드맵은 없다.** 오히려 방향이 반대다

### 타입캐스트 (현재 사용)

```
Base      https://api.typecast.ai
인증      X-API-KEY 헤더
엔드포인트 POST /v1/text-to-speech
파라미터   text(≤2,000자) · model(ssfm-v30) · voice_id · language("kor" 명시) · seed(재현성)
          · prompt(preset/smart) · output.audio_format · output.target_lufs(-14, volume 과 배타)
출력      WAV 44.1kHz 모노
```

**2026-09-05 리서치 실측 (typecast-knowhow · 크레딧 0 소모 검증):**

- **크레딧 = 글자 수.** 00002 전체 1회 합성 ≈ 378자. **한 편 = 재합성 포함 ~1,200크레딧으로 잡아라**
- **플랜 실측 (2026-09-05, `GET /v1/users/me/subscription` 로 직접 재검증)**: 이 API 키는
  **free 플랜** — 15,000 중 6,225 사용(잔여 8,775), 동시 요청 2개. ⚠️ **Studio(웹) 구독과
  API 구독은 따로 청구된다** — 웹 유료 구독은 API 크레딧을 주지 않는다. 업그레이드는
  API 콘솔(studio.typecast.ai/developers/api/pricing)에서: Lite $15/월 200k(동시 5) ·
  Plus $280/월 4M(동시 15). 실패한 요청은 크레딧 미차감.
  "1크레딧=1글자"는 자체 사용량으로 교차검증됨 — 00002 재합성 1회에 used_credits 가
  대본 글자 수(378)만큼 정확히 증가 (이 키가 우리 합성에 실제 쓰이고 있다는 증명이기도 함)
- **Studio(웹) 플랜 현황 (2026-09-05 스크린샷 실측)**: 사용자는 **Studio 베이직 ₩9,900/월 구독 중**
  (30k 크레딧·상업적 사용 가능 명시). "별도 구독·별도 과금"은 공식 FAQ 로도 확인.
  ⚠️ **음질·표현력은 플랜 게이트가 아니다** — 어느 플랜이든 같은 모델·보이스로 합성되고,
  프로(₩39,000)의 "스마트 이모션·끊음 조절"은 웹 에디터 수동 편집 UI 기능이다 (API 는
  free 키로도 감정 파라미터가 열려 있음 — 우리는 정체성 훼손으로 기각, pitfalls §10).
  크레딧이 모자라면 올릴 것은 Studio 가 아니라 **API Lite $15/월(200k ≈ 월 160편)**.
- **라이선스 적대적 검증 (2026-09-05, license-audit — 한/영 약관·이용정책·FAQ 원문 대조)**:
  - **판정: "해지하면 기존 영상 소급 침해" 주장은 오독.** 위험도 **Studio 낮음 / API 중간(문서 공백)**
  - **Studio — 해지 후 사용 명시 보장 3중 확인**: 공식 FAQ "구독을 종료하여도 **영구적으로 사용이
    가능합니다** … 해당 콘텐츠를 내리지 않아도 됩니다" + 한국어 약관 제2조 제2항 "구독기간이 끝난
    후에 … 사용하는 것에는 **제약이 없습니다**"(재가공·재다운로드만 재구독 필요) + 이용정책 동일.
    오독의 발원지: **영어판** 소유권 문장에만 "during your valid Subscription Period" 한정어가
    있음 — 한국어판(더 최신 2026-09-01, 준거법 대한민국)에는 없음
  - **API — 공백**: 한국어 API 약관 제8조 2항 4호는 "본 약관에서 별도로 정하는 바에 따릅니다"라는
    **순환 참조**뿐, Studio 식 영구 사용 보장 문장이 API 약관 안에 없다. 종료로 소멸한다는 조항도
    없다 — 리스크는 침해가 아니라 **문서 공백**. ⚠️ **free 플랜 API 생성물은 상업 이용 명시 금지**
  - **ElevenLabs 반전**: "해지 후 무기한 상업 사용" 주장도 **약관에 근거 없음** — 존속(survival)
    조항이 없고, 상업권이 Output 이 아니라 "Services" 에 붙어 타입캐스트 영어판과 구조 동일.
    이 쟁점에선 **타입캐스트가 오히려 3개 문서로 더 명확**하다. 벤더 교체는 이 리스크를 안 줄인다

## 4. 배포 — 자체 호스팅 vs 유튜브

**결론: 유튜브를 쓴다.** 자체 CDN(S3+CloudFront+HLS)을 구축했다가 **전량 제거했다.**
유튜브 대비 이점이 크지 않고, CORS·코덱 분기·환경 분리를 전부 직접 떠안게 된다.

자체 호스팅을 다시 검토하게 되면 아래를 먼저 볼 것 — 전부 실제로 부딪힌 것들이다.

- ⚠️ **FE 배포 버킷에 영상을 두면 안 된다.** 배포가 `aws s3 sync --delete` 면 다음 배포에 지워진다
- ⚠️ **S3 는 `.m3u8`/`.ts` Content-Type 을 자동 인식하지 못한다.**
  `application/vnd.apple.mpegurl` / `video/mp2t` 를 명시해야 한다
- ⚠️ **CORS 가 필요하다.** 사이트와 CDN 이 교차 출처면 hls.js 가 XHR 로 세그먼트를 받아야 하므로
  CloudFront Response Headers Policy 를 붙여야 한다. iOS 네이티브 HLS 는 없어도 되지만 Android Chrome 이 막힌다
- ⚠️ **Chrome 의 `canPlayType('application/vnd.apple.mpegurl')` 함정** — `''` 도 `'maybe'` 도 아닌 값을 돌려준다
- 환경별로 나누지 말고 한 버킷에 두고 **버전을 경로로** 가르면(`v1/`,`v2/`) 교체·롤백이 상수 한 줄이 된다
- MediaConvert 는 이 규모에 비싸지 않다(3.7분 3화질 ≈ $0.22/회). 다만 IAM·엔드포인트·잡템플릿 세팅이 붙으므로
  **영상 한 편이면 로컬 ffmpeg 이 낫다**

적응형 사다리를 다시 만들게 되면 이 수치에서 출발하라 (스크립트는 폐기와 함께 삭제됐다):

```
1080p  CRF 23 / maxrate 2.6M   →  23MB
720p   CRF 24 / maxrate 1.4M   →  14MB
480p   CRF 25 / maxrate 0.7M   →  8.7MB
```

⚠️ 처음에 CBR 4000k 로 잡았더니 1080p 가 99MB 로 4K 원본과 같아졌다.
**화면 콘텐츠(평면 배경·텍스트·정지 스샷)는 압축이 잘 먹으므로 CRF 기반 + maxrate 캡**으로 잡아야 한다.
