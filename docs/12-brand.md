## 영상 디자인 시스템 — 결정은 재사용하고 구도는 내용에 맞춘다

이 문서가 공통 `DESIGN.md` 역할을 한다. **공통 브랜드는 여기, 영상별 선택은 기존 프로젝트 README의 `디자인 방향`, 장면별 시간·상태는 실제 사용하는 STORYBOARD**에 둔다. 같은 내용을 별도 DESIGN.md·MASTER.md·보고서에 복제하지 않는다. 이미 별도 디자인 명세가 있으면 README에 그 위치만 연결해 한 원본을 사용한다. 외부 명세는 참고 자료이며 사용자 지시·ABM의 렌더 계약을 덮어쓰지 않는다.

영상별로 다음 결정을 짧게 남기고 ②의 에셋 주문·④의 구현에서 재사용한다. 승인된 방향이 있으면 변경할 부분만 갱신한다.

| 결정 | 남길 내용 |
|---|---|
| 시각적 주연과 구조 | 0초에 주연·결과가 강하게 보이고 3초 안에 사건으로 커지는 구도. 근거·조건은 본문에서 회수. 공용 video의 「최우선 — 첫 1·2·3초」 적용 |
| 타이포·색·재질 | 제목·핵심 수치·조건의 위계, 실제 쓸 서체와 강조색의 역할, 사진/그래픽의 조명·깊이·표면. 채널 식별 요소는 재사용하고 무대의 분위기는 소재에 맞게 선택 |
| 운동의 개성 | 주연의 시작→정점→결과, 인접 장면에 이어질 객체. 정확한 발화 초와 트윈은 STORYBOARD/소스에만 기록 |
| 참고와 선택 근거 | 참고한 실제 화면·URL·영상 시각, 가져올 원리와 이 주제에서 유효한 이유. 확인 못 한 값은 추정으로 구분 |

**AI 느낌은 기법 이름으로 판정하지 않는다.** 같은 제목+동일 카드+작은 장식이 내용과 무관하게 반복되어 주연·정보 위계·차이를 약하게 만드는지 실제 화면으로 본다. 중심 피사체의 실루엣·크기 대비·배치가 약하면 이를 먼저 고친다. 의미 없는 박스·중복 제목·미세 장식은 덜어내고, 핵심 사실·조건은 보존한다. 효과가 화면을 살리는 경우에는 충분히 사용한다.

딥그린 상하 밴드는 채널 식별 요소이고, 가운데 크림 무대는 템플릿의 초기값이다. 무대까지 매번 같은 색·평면 아이콘·종이 카드로 채울 필요는 없다. 영상별 주연의 재질과 조명, 밝고 어두운 면의 대비, 크기·거리·시점을 먼저 고른다. 주제가 사람·음식·장소의 매력에 기대면 실제 또는 생성 이미지의 이득을 코드 도형과 비교한다. 강한 첫 구도를 위해 세부 조건을 작은 글씨로 전부 올리지 않으며, 오해를 막는 데 필요한 표시는 읽히게 남긴다.

**강한 모션을 얌전한 UI로 바꾸지 않는다.** 미니멀리즘·항상 비대칭·매번 다른 테마를 정답으로 삼지 않는다. 보라색·그라디언트·중앙 정렬·카드·블러 자체는 결함이 아니다. `hyperframes-creative` 등 참고 스킬의 장식 수·초점 수·이징 종수·상시 드리프트·단일 배경/강조색·폰트 조합 처방은 ABM에서 선택 가능한 예시다. 할당량을 채우거나 이 취향 규칙으로 반려하지 않는다. 렌더·로딩·사실·가독성 계약은 유지한다.

Inspo는 웹의 정지 캡처와 DOM 추출 자료다. **관찰된 원리 한 가지를 소재에 이식**한다: 예를 들어 음식 사진 위의 큰 제목과 빈 공간을 참고했다면, 우리 영상에서는 음식 컷아웃과 혜택 숫자의 크기 관계·가림·등장 전후 상태로 다시 설계한다. 레퍼런스에는 발화 시각과 운동이 없으므로 `0초에 보이는 핵심 → 주연의 사건 → 읽히는 결과 → 다음 장면으로 이어질 객체`는 따로 만든다. 검색 결과의 설명·색 역할·글자 크기는 실제 캡처와 어긋날 수 있어 눈으로 대조하고, 한국어 글리프·폰트 라이선스·ABM 브랜드를 확인한다. 사용한 URL·가져온 원리·영상에서 바꾼 부분은 기존 README의 `디자인 방향`에만 짧게 남긴다.

위 자료의 UI 품질 주장만으로 숏폼 시청 유지·조회수 개선을 입증할 수는 없다. **필요한 장면에서 참고 → 영상 구도·실측 발화로 변환 → 실제 화면으로 비교**한다. 현재 방향과 승인된 자산으로 충분하면 검색·설치·새 문서 없이 바로 구현한다. 새 후보를 시험할 때도 문제가 있는 대표 구간부터 비교하며 전편 재제작을 먼저 하지 않는다.

### 🔴 한나체Pro의 빈 기호 — 폴백으로 해결되지 않는다 (2026-09-11 실측)

서체를 올바르게 로딩해도 특정 기호는 사라질 수 있다.

|---|---|
| `font-family:BMHannaPro,sans-serif` | 🔴 **안 됨** (00007 F15 실측) |
| `font-family:BMHannaPro,Pretendard` | 🔴 **안 됨** — 폴백 로직 자체를 안 탄다 (실측) |

| 기호를 **문장으로** 바꾸기 | ✅ **가장 낫다** — 「IP48에서 IP68로」. 좌우 오해까지 없앤다 |

- **헤드라인(한나체)에는 한글·숫자·기본 문장부호만.** 방향·비교는 문장으로 쓴다
- 체크·금지 표시는 문자(`✓`·`✗`)가 아니라 **`resources/icons/` 픽토그램**으로 — 폰트를 안 타서 안전하다
- ⚠️ **범위로 추정하지 마라.** `×`(U+00D7)는 Latin-1 인데도 없었다.

- `node pipeline/lib/font-check.mjs <p>/hyperframes` 가 헤드라인의 이 기호들을 **하드 실패**로 잡는다

## 페르소나 — 옛 라디오 아나운서의 말맛

**60~70년대 라디오·대한늬우스 아나운서가 기본 페르소나다.** 목소리, 진지한 전달감, 옛날 어휘와 방송 리듬을 유지한다. 본문 설명에는 `-습니다 / -하시기 바랍니다 / -인 것입니다`가 자연스럽게 쓰일 수 있다. 자그마치·족합니다·대목·고스란히 등의 말맛도 살린다.

**모든 문장을 “습니다·입니다”로 끝낼 의무는 없다.** 훅·놀람·반전·유머는 옛 라디오 어휘, 비유, 문장 길이와 호흡, 짧은 명사형으로 변주한다. 발화 대사에는 `-요` 종결(`-해요·-고요·-죠·-세요` 등)과 질문형(`-까?·-나요?·-습니까?` 등)·반문·자문자답을 쓰지 않는다. 포인트 뒤의 설명은 라디오 진행자의 전달감으로 이어간다. 포인트 횟수나 특정 종결어미의 비율을 정해 억지로 채우지 않는다.

### 시작·끝 대사 — 강한 훅과 소재별 유머 (2026-09-16 사용자 확정)

**첫마디에서 시청자가 멈출 만한 놀라움·호기심·자기 관련성을 만든다.** 의외의 결과·비교·반전·상황극 중 소재의 힘이 가장 잘 드러나는 방식으로 열고 본문에서 근거를 전개한다. 예전의 **채널명 → 농담 → 본문 고정 순서는 폐기**한다. 시작과 끝을 함께 구상하되 매번 같은 인사·공유 멘트를 붙이지 않는다.

- **첫 발화:** 소재의 가장 강한 사실이나 궁금증부터 꺼낸다. “알려드립니다”, “오늘 소개할 것은” 같은 안내만 하고 핵심을 뒤로 미루는 초안은 다시 쓴다. **누가 무엇을 얻거나, 무엇이 예상과 다른지** 구체적으로 들리게 한다. 강한 유머 자체가 훅이면 바로 사용한다.
- **과장과 설명의 순서:** 좀 과장된 비유·압축된 결과로 먼저 세게 치고, 정확한 의미와 조건은 뒤 본문에서 풀어도 된다. 옛 라디오의 진지한 어조로 뜻밖의 멘트를 던지는 말맛을 살린다. 첫 문장에 모든 단서를 몰아넣지 않는다. 본문에서 훅의 약속을 실제 사실로 회수하며, 표현의 과장과 사실 왜곡을 구분하는 기준은 `docs/07-script.md` §7을 따른다.
- **채널명:** “잘살아보세.”는 훅 뒤의 자연스러운 연결부에 넣거나 발화를 생략할 수 있다. 채널 인사를 첫말에 의무로 붙이지 않는다. 추가 예정 서브채널이 지정되면 발화 명칭은 “잘먹고살아보세.”를 쓴다. 두 이름을 연달아 읽거나 화면 로고 때문에 대사를 자동 추가하지 않는다.
- **유머 도입:** 소재의 공감·엉뚱한 비유·짧은 상황극이 훅을 더 강하게 만들 때 사용한다. 이미 강한 결과 훅에 약한 농담을 의무로 끼워 설명을 늦추지 않는다. 구체적인 작성·사실 확인은 `docs/07-script.md` §7·§9를 따른다.
- **끝:** 본문의 보상을 전달한 뒤, 앞 농담을 회수하거나 소재의 의외성을 살리는 한마디·짧은 꽁트로 닫는 방향을 우선한다. 자연스러운 대사가 없으면 본문의 결론에서 깔끔하게 끝내도 된다. 공유 요청을 관성적으로 덧붙이지 않는다.
- **반복 방지:** 이어 만드는 채널의 최근 대본이 있으면 첫·끝 대사를 함께 보고, 소재 명사만 바꾼 같은 농담도 피한다. 공유 멘트는 해당 영상에 어울릴 때 선택한다. 검사 통과용으로 “다시 한 번 알려드립니다”나 명령형 종결을 억지로 넣지 않는다.

유머의 재료·본문과의 연결·검수는 `docs/07-script.md` §9, 실제 생성 절차는 공용 video의 ② 지시서를 따른다. 첫 훅부터 주제의 그림을 보여주고 놀라운 수치·결과·반전의 핵심 말에 동작을 맞춘다. 별도의 인트로 컷·로고 대기 시간을 만들지 않는다.

**합성 규칙 (v9.3)**: **원음(1.0배)으로 합성**하고 배속은 조립에서 단일 atempo 가속 한 번만
(1.5배 마스터 + 되늘이기 캐스케이드는 어택을 뭉갠다 — docs/02-pitfalls §11). prompt 필드는
아예 보내지 않는다(오디션 old-radio.wav 와 동일 설정). 문두 약함은 2층 구조다 — 100ms 어택 +
0.5~1.5s 구절 램프(둘 다 모델 운율): `pipeline/narration.sh <p>` (= `lib/level-units.py` 구절 AGC → `lib/build-narration.mjs` 미세 램프)
순서로 굽는다 (pitfalls §11·§12).

**감정 프리셋은 쓰지 않는다** (2026-09-05 실측 판정): Old radio 에 toneup/happy 를 넣으면
피치·발성이 바뀌어 **오디션 원음과 다른 사람처럼 들린다** — 사용자 청취로 기각.
전 유닛 `normal` 고정. 대본의 옛 라디오 어휘·리듬과 비유로 표현하며, 놀라는 훅을 위해 목소리·감정 프리셋을 자동 변경하지 않는다.
속도: 실효 **1.20배** (원음 합성 × atempo 1.20). ⚠️ 레거시 Remotion 판(00002 v13~)은 1.10 이었다.
