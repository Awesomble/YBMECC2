# resources/logos/ — 주제 브랜드·기관 CI

**영상 주제가 특정 브랜드·기관·상품이면 그 CI(로고)를 여기 넣는다.** 잘살아보세 자체 마크는 `../brand/` 다 (헷갈리지 마라).

```
resources/logos/<브랜드슬러그>.png    심볼 — **투명 PNG(rgba), 1000px 이상**
resources/logos/SOURCES.md          한 줄씩: 파일명 · 출처 URL · 받은 날짜
```

파일이 여럿인 브랜드는 `<슬러그>-wordmark.png` 처럼 접미사를 붙인다.

한 번 넣으면 **여러 영상에서 재사용한다.** 쓸 때는 그 영상 폴더로 복사한다 —
`projects/<p>/assets/scene/` 에 있는 것만 렌더에 스테이징된다 (라이브러리 전체를 번들에 넣지 않는다).

```bash
cp resources/logos/burgerking.png projects/00003-버거킹와퍼/assets/scene/brand-logo.png
```

## 🔴 회수 — 한 바퀴를 닫아라 (2026-09-16 사용자 지시)

> *"상표·로고·CI 등은 수집 후 나중에 재사용할 수 있게 리소스 폴더에 잘 정리하는 것도"*

**복사는 라이브러리 → 프로젝트 한 방향인데, 새로 구한 것은 프로젝트에서 생긴다.** 그 한 바퀴가 안 닫혀 있었다.
2026-09-16 실측: 프로젝트에만 남아 있던 **규격 통과 자산 16종** — `bbq-logo.png`(1400×620 rgba) ·
`pb-wordmark.png`(2000×144 rgba) · `apple.png`(843×1000 rgba) 등. 라이브러리엔 SVG 만 있어서
**래스터가 필요한 다음 영상은 또 구해야 한다.**

```bash
node pipeline/logo-check.mjs        # 맨 아래 📦 절이 「라이브러리에 없는 규격 통과 자산」을 센다
```

**한 바퀴 — 수집 → 검사 → 회수 → 기록**

| | |
|---|---|
| ① 수집 | 공식 브랜드 리소스·보도자료에서. 검색 이미지는 쓰지 마라 |
| ② 검사 | `logo-check` 통과본만. **불합격은 회수하지 마라** — 라이브러리가 더러워진다 (`traders` 668×259 rgb24 가 그 예다) |
| ③ 회수 | **로고·CI → `resources/logos/`** · **제품·소재 사진 → `resources/images/`**. 섞지 마라 |
| ④ 기록 | `SOURCES.md` 에 **한 줄**. 🔴 **출처를 못 적을 파일은 회수하지 마라** — 내가 배경을 키운 파일(`golden-olive-cut` 류)은 원본이 아니다 |

**언제**: ⑥ 문안 단계에서 그 영상을 닫을 때. `stage-gate <p> 6` 이 미회수분을 경고한다.

### 이름 규칙

```
<슬러그>.png              심볼 (기본)
<슬러그>-wordmark.png     글자 로고
<슬러그>-<색>.svg          색 변종 — bbq-red.svg · bbq-white.svg
<슬러그>-mono.png         단색판 — mcst-mono.png
<슬러그>-old.png          교체된 옛 판 (쓰지 마라. 되돌릴 때만)
```

## ⚠️ 지금 들어 있는 로고는 그대로 쓰면 안 된다 (2026-09-07 실측)

```bash
node pipeline/logo-check.mjs        # 라이브러리 전체를 잰다 (불합격이 있으면 exit 1)
node pipeline/logo-check.mjs <p>    # 그 영상의 assets/scene/ 까지 함께
```

| `burgerking-old.png` | 342×340 | **rgb24** | 흰 사각형. `burgerking.png` 로 **교체 완료**(2026-09-08) — 백업본이다 |

🔴 **이 표를 손으로 고치지 마라. `node pipeline/logo-check.mjs` 가 정본이다** (2026-09-16 갱신).
옛 표는 `burgerking.png` 를 불합격으로 적어 두고 있었는데 **2026-09-08 에 이미 교체돼 통과**였다 —
문서가 낡으면 멀쩡한 자산을 안 쓰게 된다.

알파가 없으면 딥그린 위에서 **그 브랜드 색 사각형**이 그대로 뜬다 — 로고가 아니라 색판이 보인다.
1000px 미만이면 220px 로 써도 확대 여유가 없다.

① 분석 단계는 파일이 있으면 "있다"고 판단하기 쉽다. 그래서 **도구로 잰다.**
불합격이면 투명 PNG 1000px 이상으로 다시 받고, 안 되면 사용자에게 요청한다.
⚠️ **배경을 키잉해서 알파를 만들지 마라** — 아래 "변형 금지"에 걸린다. 원본을 다시 받는 게 맞다.

## ⚠️ 남의 상표를 화면에 쓰는 규칙 — 이건 지켜야 한다

이 채널은 상표 리스크 때문에 이름을 **잘살아보세**로 정했다 (`docs/12-brand.md`).
**사실을 전달하려고 대상을 식별하는 용도**는 통상 허용되는 범위지만, 아래를 넘으면 성격이 달라진다.

| 된다 | 안 된다 |
|---|---|
| 어떤 브랜드의 행사인지 알리려고 원본 로고를 그대로 표시 | 로고를 **변형·합성·재배색**하거나 우리 로고와 섞기 |
| 공식 자료(포스터·보도자료)에 있는 사실을 전달 | 공식 채널·제휴·후원인 것처럼 보이게 배치 |
| 제품 사진을 정보 전달용으로 사용 | 브랜드 로고를 채널 락업 자리에 두거나 더 크게 키우기 |

- **유튜브 명의 도용 정책**은 전반적 디자인·분위기 모방까지 채널 폐쇄 사유로 본다 ([정책](https://support.google.com/youtube/answer/2801947?hl=ko))
- 로고는 **브랜드존(y226 락업) 밖**, 페이로드 안에 둔다. 우리 마크보다 크게 만들지 마라
- 상업 브랜드를 다루는 편은 설명란에 **"해당 브랜드와 무관한 정보 안내"** 한 줄을 넣는 것을 권한다
- 제품 사진은 **출처가 명확한 것만** — 공식 보도자료·브랜드 리소스 페이지. 검색 이미지를 그냥 쓰지 마라.
  `SOURCES.md` 에 URL 을 남긴다

**판단이 안 서면 넣지 말고 사용자에게 물어라.** 지우는 것보다 안 올리는 게 싸다.

## 설계 노트 — 로고를 **카드 안**에 넣으면 그 카드가 모션에서 빠진다 (2026-09-10 · 00006)

「로고와 그 **조상**에 트윈 금지」는 지켜야 하는데, 로고를 비교 카드 안에 두면
**카드 자체를 못 움직인다.** 움직일 수 있는 건 로고의 형제(`.label`·`.amount`·`.condition`)뿐이다.
00006 에서 이 제약이 비교 프레임의 모션 밀도 상한을 만들었다 (F01 12 · F22 17,
다른 프레임은 20~52).

**다음에 이 레이아웃을 다시 쓴다면**: 로고를 카드 **밖**의 같은 좌표에 형제 레이어로 두어라.
그러면 카드는 모션에 쓰고 로고는 정지시킬 수 있다.

⚠️ 가이드라인은 **로고에 효과를 거는 것**을 금지한다. 컷 전환으로 로고가 나타나고 사라지는 것,
로고를 화면의 다른 자리에 배치하는 것 자체는 막지 않는다. 다만 **로고가 얹힌 바탕이 변하는 것**도
「효과를 준 것」으로 읽힐 수 있으니, 카드를 움직인다면 로고는 그 카드와 **완전히 분리**돼야 한다.
