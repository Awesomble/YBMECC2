# ① 사실과 자산

공용 SKILL.md의 현행 절차를 따른다. 결과는 프로젝트 README.md의 확정 팩트와 assets/scene/다.

0. **YBMECC:** 이 채널의 1차 자료는 원장 꼭지와 원생 사진이다. 사진은 `node pipeline/photo-intake.mjs <p>`로 들이고 README 「## 사진 동의」를 연다(동의 ✅ 전에는 화면에 쓰지 않는다). 원장만 아는 사실(활동·일정·정원·교습비)은 확정 팩트 표의 근거 칸에 「원장 확인 YYYY-MM-DD」로 적는다 — 공개 출처가 없는 값이라 교차검증 대상이 아니며, 확인이 없으면 대본에 쓰지 않는다. 금지·주의 표현은 `node pipeline/academy-check.mjs <p> 2`(채널02 §1).
1. 사용자 원본(이미지·URL)이 있으면 직접 보고 작은 조건 문구까지 확인한다. 주제만 받았으면 웹 검색으로 1차 출처를 찾는다. 도구는 각자 가진 이미지 보기·웹 도구를 쓴다.
2. 가격·기간·대상·한도·예외·중복 적용·결제수단·조기 종료를 1차 출처로 확인한다. 바뀔 수 있는 정보는 현재 공식 자료를 조회한다.
3. 출처의 게시일과 행사일을 구분한다. 연도 없는 포스터의 요일은 추정 단서일 뿐 확정 근거가 아니다. 종료된 행사를 현재 혜택으로 소개하지 않는다.
4. 공식 페이지가 JS 때문에 비어 보이면 `node pipeline/cf-crawl.mjs <url>`을 가능한 환경에서 사용한다. 읽지 못한 내용을 불일치나 사실로 단정하지 않는다.
5. **조사 에이전트·검색 요약이 준 인용문은 팩트 표에 넣기 전에 그 URL에서 문장을 직접 대조한다.** 열 수 없으면 `확인 못 한 것`에 두고 대본이 그 문장에 기대지 않게 한다. 대사에 쓸 주장만 조사시키고, 쓰지 않을 배경 사실은 묻지 않는다. (00006: 다른 페이지의 문장을 인용했다가 독립 검증에서 드러나 대본 두 줄·시간축·자막을 다시 만들었다.)
6. 가장 유용한 메시지와 빠뜨리면 오해할 조건을 고른다. 마감·돈·숫자가 없다는 이유만으로 사용자가 요청한 주제를 반려하지 않는다.

## 기록과 독립 확인

팩트시트를 **먼저** 작성한 뒤 메인과 분리된 검증 에이전트로 교차검증한다.

```markdown
## 확정 팩트 (검증일 YYYY-MM-DD)

| 항목 | 확인한 값·조건 | 근거 URL | 등급 |
|---|---|---|---|
| 대상 | 실제 확인한 내용 | 공식 원문 | 1차 |

확인 못 한 것: 없음 또는 미확인 항목과 처리
```

```bash
# 검증 에이전트: node pipeline/cross-verify.mjs <p> → 패킷대로 검증 → .cross-verify/raw.txt → node pipeline/cross-verify.mjs <p> --record
node pipeline/stage-gate.mjs <p> 1   # 메인: 기록 확인만 (패킷을 직접 뽑아 컨텍스트에 덤프하지 않는다)
```

**검증자는 메인과 분리된 에이전트다.** Claude는 `video-verify`에 프로젝트 번호만 넘긴다 — 에이전트가 패킷을 받아 1차 출처를 처음부터 다시 찾고, 답 JSON을 `.cross-verify/raw.txt`에 써서 `cross-verify.mjs <p> --record`까지 직접 실행한 뒤 판정표만 돌려준다. Codex가 메인이면 세션의 별도 검증 에이전트에 같은 절차를 맡기고 같은 모델의 독립 실행임을 README에 밝힌다. 메인은 패킷·raw.txt·result.json을 쓰거나 고치지 않는다. **Codex를 리서치·교차검증 도구로 부르지 않는다**(2026-10-02 사용자 지시 — 옛 `codex exec` 검증 폐기).

기록은 팩트·refs 지문이 패킷을 낸 때와 같을 때만 남고 24시간 유효하다. 빈 claims·형식 오류·누락 항목·불일치/확인불가가 남은 결과는 통과하지 않는다. 불일치는 1차 출처로 해결하고, 확인불가 항목은 대본에서 빼거나 확인한다. missing_conditions·risky_phrasings는 대본 표현에 반영한다. 통과 뒤 메모는 별도 `## 교차검증` 절에 쓰고 `## 확정 팩트`는 고치지 않는다 — 고치면 지문이 바뀌어 다시 검증해야 한다.

**한 번에 통과시키는 준비:** 대사에 쓸 주장만 행으로 둔다(로고 같은 자산은 행이 아니다). 행마다 1차 출처 URL·원문 그대로의 인용·게시일/범위를 적고, 그 원문을 `assets/refs/`에 텍스트로 저장한다(JS 페이지는 `cf-crawl.mjs`). 2차 자료만 있는 행은 등급을 2차로 밝히거나 1차 원문으로 다시 근거를 잡는다(00031·00034는 이 준비가 없어 두 번 돌렸다).

## 브랜드와 그림 재료

- 브랜드·기관이 주제면 공식 CI를 resources/logos/에서 찾고, 없으면 공식 자료에서 확보한다. 실제 제품 사진도 원본을 사용한다.
- resources/logos/README.md의 상표 사용 지침과 `node pipeline/logo-check.mjs <p>`로 실제 자산을 확인한다.
- 채널 로고는 확보할 자산이 아니다. 공용 SKILL 기술 계약 표의 좌상단 로고(`resources/brand/ybmecc-daechi-tab.png` — YBM ECC 대치점)를 골격이 넣는다.
- 새로 확보한 공유 자산은 해당 라이브러리와 기존 출처 장부에 URL·날짜를 기록하고 프로젝트로 **복사**한다.
- 실제 CI·제품 원본을 확보할 수 없으면 필요한 자산만 요청한다. 사용자가 생략을 승인한 경우 그 범위에서 진행한다. 유사 로고를 만들어 채우지 않는다.
- 기존 아이콘·제품·사진 중 무엇을 어디에 쓸지 README에 적어 ④에 전달한다. 파일 개수를 목표로 삼지 않는다.
- 필요한 에셋마다 기존 원본·코드·Blender 3D·이미지 생성의 조합을 공용 SKILL 「에셋 제작 경로」로 판단해 ②에 넘긴다. **주연 사물·건물 외관/부분 요소의 3D 후보와 매핑할 표면을 적극 정한다**(docs/16-blender.md §1·§5-1). 표면 이미지는 이미지 생성(②)이나 공식 원본으로 확보한다(외부 사진 금지 — 공용 SKILL 「에셋 제작 경로」). 실재 장소·건물·음식·제품을 그릴 이미지·3D는 ②에서 실제 사진 여러 장을 분석한 뒤 만든다(`ref-photos` — 분석 전용, ② 「실물 대조」·docs/16 §4-1). 공간 전체를 조사·모델링 범위로 자동 확장하거나 가격·제도 주제라는 이유로 사물 후보를 제외하지 않는다. 코드로 그릴 수 있어도 매력·질감·전달력이 좋아지면 생성 후보로 잡는다. 생성물은 실제 CI·제품·사실의 증빙을 대체하지 않는다.

①과 ②의 결과를 묶어 A 보고로 올리고 같은 턴에 ③으로 간다 — 팩트와 대본을 따로 올려 왕복을 늘리지 않는다. 여기서 멈추는 것은 교차검증 실패(불일치·확인 불가가 대본에 남을 때)뿐이다(공용 SKILL 「제작 흐름」).
