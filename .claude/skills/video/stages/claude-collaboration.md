# Codex 메인 + Claude Code Opus 5.5 — 선택 협업

**이 파일은 video 작업에서 사용자가 Claude Code 병행을 명시했을 때만 읽는다.** 설정 요청 자체로 제작이나 모델 호출을 시작하지 않는다. 구독을 효율적으로 활용하되 결과물 품질이 우선이다. **Advisor는 사용하지 않는다.**

## 활성화와 책임

- 예: `$video 3번 만들어줘. 클로드코드도 사용해.` / 진행 중인 영상에서 `이번에는 Claude Code도 같이 써`.
- 현재 작업의 명시적 사용자 문장을 작업 패킷에 기록한다. 같은 작업의 수정에는 재승인을 요구하지 않는다. 새 영상·별개 작업은 기본 해제, 사용자의 중단 지시는 즉시 적용한다.
- Codex가 사용자의 유일한 총괄 창구다. 조사 결과를 판단하고 연출·파일 소유권·검사·수정 순서를 정한다. Claude에 전체 `/video`를 통째로 넘기지 않는다.

## 무엇을 누가 하는가

| 작업 | 담당과 인계 결과 |
|---|---|
| 콘텐츠 약속·훅·메시지·스토리보드 결정 | Codex. Claude의 자료·한국어 표현 후보를 받아 최종 결정 |
| 공식 자료 확인·문장 다듬기 | 원문을 확보한 쪽이 결과를 전달한다. Claude에는 미해결 범위 또는 확보한 원문 발췌의 검토를 배정한다. 양쪽이 같은 검색을 다시 하지 않는다. 필수 독립 교차검증은 별도 유지 |
| 대표 모션·카메라·공간 관계·컷 간 연결 | Codex. 실제 root 0초 및 0~3초를 먼저 구현·재생 확인 |
| 반복 SVG/장면 코드·독립적인 본문 컷 | Claude Opus 5.5가 실제 파일을 구현한다. 이야기상 연결된 본문을 한 묶음으로 주고, Codex가 같은 코드를 병행 작성하지 않는다. Codex는 완료 diff·실제 화면·인접 연결을 검수 |
| 복잡한 원인 분석·구조 변경·여러 컷의 의미 연결 | Codex. Claude에는 좁힌 증거 수집이나 재현 분석만 맡길 수 있음 |
| 정적 누락·문구·경계 조건 검토 | 구현자와 분리한 Claude 검토 또는 기존 검수 경로. 같은 결과를 양쪽이 전부 다시 조사하지 않음 |
| root·cuts·음성·공유 자산·엔진·문서 반영·검사 실행 | Codex. Claude 워커는 직접 변경하거나 도구를 실행하지 않음 — 훅 잠금의 `hook-check`도 Codex가 돌리고, 훅 워커는 첫 컷 소스의 첫 트윈·정점 시각과 네 행별 구현 근거만 보고한다 |
| 실제 연속 재생·최종 화면 판정·사용자 전달 | Codex. Claude의 코드 검토가 시각 검수를 대체하지 않음 |

**도입부만 등장시키고 멈추는 포스터를 만들지 않는다.** 담당 컷 패킷에는 `시작 상태 → 발화별 사건 → 정착 결과`, 시간·주연·크기 관계·연결 방향을 적는다. 예를 들어 공항철도는 “기차 등장” 대신 “급행이 중간 역을 통과하고 일반열차 문이 목적지에서 열린다”를 구현한다. 각 컷을 카드 템플릿으로 획일화하지 않는다. 모션 기법·거리·효과 수를 절감 대상으로 제한하지 않는다.

## 사용량 운영

품질·검사·사용량 집계는 공용 SKILL.md 「사용량 운영」 절을 따른다. 본문 위임 전 Codex는 훅·본문 핵심 변화·인접 연결을 실제 root에서 검증하고, root·시간·자막 계약은 ④에서 확인한다. 연결된 본문을 묶어 맡기며 같은 코드를 병행 작성하지 않는다. 조사만 맡기고 메인이 모든 컷을 재작성한 것을 협업 절감으로 보고하지 않는다.

1. **역할과 호출:** 짧은 수정·CLI 검사는 메인이 처리하고 Claude에는 충분히 큰 실행 묶음을 맡긴다. 보통 작업 1개, 소유 파일이 겹치지 않고 병렬 이득이 있을 때만 2개로 나눈다. 독립 편집 검토와 화면 검토의 역할을 유지하며 호출 수만 줄이려고 생략하지 않는다. 별도 호출 여부는 검증 범위로 정하고 일률적인 호출·토큰 상한이나 이중 팬아웃은 추가하지 않는다.
2. **모델:** `claude-opus-5-5`(Opus 5.5) 고정, effort는 `medium`(래퍼 기본값 — 2026-10-21 사용자 지시, 메인 Fable 5.1 · docs/15 「서브에이전트 모델」), 패킷이 필요할 때만 `high`·`xhigh`를 지정한다. 단순 집계·검색·정적 검사는 기존 도구를 우선한다. 전역 설정을 상속하지 않고 래퍼가 패킷마다 `--effort`를 넘기며 Advisor·Claude 내부 Agent·자동 모델 폴백은 끈다. 복잡한 판단은 Codex가 맡는다.
3. **패킷:** 공용 전달 문맥에 채널05 §3-1·worker-brief의 관련 계약(새 이해·상태 변화·이어질 객체·동시 변경 값/단위·위험 시각)을 포함해 `/tmp`에 쓴다. 전송 전 현행 정본·승인 팩트·표기 위계·단위 조건을 대조해 지시 충돌을 없앤다. 승인된 선택을 취향으로 재심사하지 않되 실제 사실 오류·조건 누락·가독성 결함은 고친다. 담당 HTML은 전체 읽고 장문 지시는 관련 절만 한 번 전달한다. 무관한 과거 사례·대화 전체·루트 전체 검색은 제외하되 필요한 근거와 연출 이유는 길어도 보존한다. 구현은 기본 `web:false`다.
4. **수정·검수:** 유지 가능한 SVG·라벨·골격은 재사용하고 필요한 구도·상태·타임라인을 수정한다. DOM 보존이나 수정량 최소화보다 주제에 맞는 재설계를 우선한다. 결과·수정 요청을 모아 기존 fix-batch와 단계 게이트로 처리하며 매 수정마다 전체 렌더하지 않는다. 핵심 의미를 반복해서 놓치면 Codex가 회수하되 한 작업의 실패를 모든 위임 중단으로 일반화하지 않는다. ①의 교차검증 캐시·절차를 재사용하고 필수 교차검증은 생략하지 않는다. Claude 보고·자동 검사로 실제 시각 검수를 대체하지 않는다.
5. **반환:** 담당·변경·검증 결과와 결함·미검증을 누락 없이, 보고 앞부분에 두어 래퍼의 2,000자 미리보기만으로 판정 근거가 보이게 한다. 미리보기에서 `result_truncated:true`이면 임시 원문의 관련 findings/unresolved를 확인한 뒤 판정한다. 미리보기만으로 성공을 승인하지 않는다. 사용량은 실제 `usage`/`modelUsage`로만 집계한다.

**모델 이상은 작업별로 처리:** `unexpected-model` 또는 `not-reported`는 성공 처리하지 않는다. 해당 결과/부분 변경을 조사하고 자동 재시도·모델 폴백을 하지 않는다. 웹 도구의 보조 모델 가능성만으로 Haiku를 허용 목록에 넣지 않는다. [Claude Code 도구 문서](https://code.claude.com/docs/en/tools-reference#webfetch-tool-behavior)는 WebFetch가 작은 모델로 내용을 추출한다고 명시한다. 이는 00003의 가능 원인이지 개별 호출 원인의 확정은 아니다. 다음의 별개 구현 작업은 현재 사용자 협업 승인 아래 `web:false`로 필요한 범위만 실행하고 실제 보고 모델을 다시 검사할 수 있다. 인증/한도/환경 전체 문제라면 해결 전까지 멈춘다. 절약 분석·설정 요청만으로 모델을 시험 호출하지 않는다.

## 호출 도구

저장소 루트에서 실행한다. **기본은 계획 출력이며 모델을 호출하지 않는다.**

```bash
node pipeline/video-claude.mjs 2 --task /tmp/abmen-claude-task.json
node pipeline/video-claude.mjs 2 --task /tmp/abmen-claude-task.json --run
```

패킷 예시(실행 때 현재 사용자의 실제 지시와 실제 담당 파일로 바꾼다):

```json
{
  "authorization": {
    "mode": "video-with-claude",
    "project": "00002-seoul-airport-train",
    "user_request": "video로 이번 영상 수정해. 클로드코드도 사용해."
  },
  "task": "승인된 상태·시간 계약에 따라 본문 컷을 구현한다. 전체 기획은 바꾸지 않는다.",
  "context": "여기에 확정 팩트, 시작→사건→정착, 이웃 컷 연결, 필요한 규칙 발췌를 넣는다.",
  "read_files": [
    "projects/00002-seoul-airport-train/hyperframes/STORYBOARD.md",
    {"path": "docs/channel/05-brand-pipeline.md", "start_line": 16, "end_line": 36}
  ],
  "write_files": ["hyperframes/compositions/frames/03.html"],
  "acceptance": ["발화별 상태 변화가 구현됨", "같은 시각 seek에 같은 화면", "담당 파일 외 수정 없음"],
  "effort": "medium",
  "web": false
}
```

- `read_files`는 저장소 상대 경로 문자열 또는 `{path,start_line,end_line}`(1부터, 양끝 포함)이다. 줄 범위는 패킷 생성 전에 제목/본문을 확인해 고르고 예시 숫자를 그대로 복사하지 않는다. 범위 내용은 프롬프트에 직접 포함하므로 워커가 문서 전체를 재독하지 않는다. 계획 출력의 `input`은 전달 바이트/전체 읽기 파일 바이트/발췌 위치이며 토큰 추정값이 아니다. 큰 입력의 경고는 필요한 근거를 자르라는 하드 제한이 아니다.
- `write_files`는 해당 프로젝트 상대 경로다. 쓰기는 담당 프레임 HTML에만 허용한다. 파일명은 실제 프로젝트를 확인한다. 조사·검토는 `write_files: []`. 공식 웹 확인은 원문 확보 담당 한쪽이 수행하고, Claude 웹 도구가 꼭 필요한 독립 조사만 `web:true`로 한다.
- 패킷의 승인 문장은 증빙을 남기는 필드이지 사용자 동의를 자동 판별하는 장치가 아니다. **현재 대화에서의 활성화 판단은 메인 Codex의 책임**이다. 예시나 이전 패킷을 동의로 재사용하지 않는다.
- 래퍼는 Max OAuth 로그인 상태를 확인하고 API 키·외부 공급자 환경이 있으면 중단한다. `--bare`는 OAuth를 쓰지 않으므로 사용하지 않는다. 사용량 제한·인증 실패 시 별도 과금으로 우회하지 말고 Codex가 작업을 이어간다.
- `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`을 자식 프로세스에 지정한다. 개인 `advisorModel` 설정과 관계없이 Advisor를 끈다. 전역 설정과 프로젝트 `CLAUDE_CODE_SUBAGENT_MODEL`은 수정하지 않는다.
- 호출은 `--safe-mode`로 중복 CLAUDE.md·스킬·훅·MCP·내부 에이전트 로딩을 끄고 필요한 지시를 패킷에 명시한다. 안전 규칙을 생략하라는 뜻이 아니다. 관리형 정책은 유지된다. 도구는 읽기/선택한 웹 확인/담당 프레임 수정만 열고 Bash·Agent·유료 음성 실행을 주지 않는다. 권한 거부는 우회하지 말고 Codex가 필요한 작업을 맡는다.
- 작업은 비대화형 JSON으로 반환하며 세션을 영구 저장하지 않는다. 전체 결과는 시스템 임시 폴더에 보존하고 stdout에는 모델 판정·사용량·짧은 결과·원문 경로를 반환한다. 원문 전체 출력은 진단할 때만 `--full-result`를 사용한다. 긴 실행은 셸 실행 도구의 세션으로 두고 Codex가 독립 작업과 사용자 업데이트를 계속한다. 자동 재시도하지 않는다. 타임아웃·부분 실패 때 이미 수정한 담당 파일을 먼저 확인한다.
- 런타임 검사는 Codex가 기존 `hf-cli`·layout-scan·stage-gate로 수행하고 실제 화면을 본다. 4-designer가 요구하는 캡처·재생 판정(360px 실루엣, 0~3초 재생, 중간 프레임)도 Codex 몫이며, 외부 워커의 "검증" 보고는 코드 검토로만 받는다. CLI 결과의 `ok`는 워커 실행 성공일 뿐 영상 검수 통과가 아니다.
