# ⑤ 최종 검수와 납품

기술 결함과 연출 완성도를 분리해 판정한다. 채널05 §2·§3-1과 프로젝트의 승인 방향이 기준이다. **통과 로그만으로 전달력·연출·청취까지 완료 처리하지 않는다.** 조회수 예측·취향·효과 개수·미세 좌표 차이는 반려 사유가 아니다.

## 렌더 전 검토 — ④의 C 준비 안에서

최신 root의 정착 시트와 대표 동작을 보고 **첫 훅의 약속 → 본문의 증거·설명 → 마지막 답**이 이어지는지 확인한다. 반복 구도로 관계가 묻히는 곳, 중요한 실물의 질감·형태가 임시 도형 수준에 남은 곳, 인접 장면의 시점·합성이 어긋나는 곳은 시각과 전달 손실을 짚어 수정한다. 의도된 비교·도식·읽기 정착은 유지한다.

구현과 분리된 검토를 이때 수행해 새 장면 설계가 필요한 문제를 전체 렌더 뒤로 미루지 않는다. 실제 최종 자산의 확대 정점·인물 실루엣·값/단위 교체·이음매는 필요한 구간을 조밀하게 본다. 성긴 타일만으로 “모션이 없다”고 판단하지 않는다. 기술 결함 / 근거 있는 연출 개선 / 취향 제안을 구분해 fix-batch로 모은다. 새 사용자 컨펌은 만들지 않는다. 이 검토는 아래 최종 MP4 대조를 면제하지 않는다.

## 실제 렌더

C 보고를 올린 같은 턴에 아래 통로로 렌더한다(렌더 상한 안에서). 권한 제한 시 처리는 공용 SKILL 「실행 환경」을 따른다.

```bash
pipeline/hf-render.sh <p> <출력.mp4>
pipeline/render-gate.sh <p> <출력.mp4>
node pipeline/hook-check.mjs <p> --from <출력.mp4>   # 🔴 첫 3초 — MP4 자체에서 0·0.25·0.5·1·2·3초 시트 + 시각 대조
node pipeline/hf-export.mjs <p>
node pipeline/ig-cta.mjs <p>                        # cuts.json ig_cta 편(지도 핀 자동 · 요청한 링크 편) — 묻지 않고 본편 위에 하단 스티커를 얹어 ig-reels-vN.mp4(같은 길이) · 시트 review/ig-cta-sheet.png
node pipeline/review-page.mjs <p>
node pipeline/stage-gate.mjs <p> 5 --video <출력.mp4>
```

HyperFrames의 자막·타임라인과 유튜브 커버 `output/cover.jpg`(납품 MP4의 0초 한 장)는 **hf-export**로 만든다 — 커버가 없거나 MP4보다 오래되면 단계 5가 막는다. 레거시 export.mjs로 덮지 않는다.
검수 대상 MP4가 현재 소스와 같은 판인지 게이트 결과로 확인하고, 독립 감독은 hf-export까지 끝난 뒤 맡긴다(먼저 맡기면 낡은 SRT를 결함으로 본다). 이미 통과한 동일 판의 측정을 이유 없이 반복하지 않는다.
렌더 전 납품 준비 항목만 볼 때는 단계 5에 `--prepare`를 붙인다. 이 결과를 납품 완료로 쓰지 않는다.
실행하지 못한 검사는 미검증이라고 적는다. 체크리스트만 보고 통과시키지 않는다.

## 본다·대조한다

**채널05 §3-1의 기준으로 정착뿐 아니라 변화 과정을 판정한다.** STORYBOARD의 강조 계약과 위험 시각을 최종 MP4에서 대조한다. 훅과 본문의 핵심 발화에 자막 임팩트·화면 변화가 실제로 들어갔는지, 선택한 보조 그래픽·소리가 계획대로 작동하는지 확인한다. 핵심 강조 누락·계획 미구현은 수정 필요로 판정한다. 가격·통화·단위·대상 묶음의 교체 전/중/후, 주연이 글자 근처를 통과하는 순간은 필요한 만큼 조밀하게 추출한다. 정착 시트·기술 게이트가 놓친 이동 중 결함 사례는 docs/02-pitfalls.md §112이며, 기준작의 결함은 복제하지 않는다.

첫 훅과 함께 본문 핵심 변화·장면 연결·마지막 선택을 본다. 새 정보 없이 같은 비교를 반복하거나 전환 장식만 바뀌는 구간은 무엇을 이해하기 어려운지 짚고 기존 기획 범위에서 구조를 보완한다. 읽는 정착을 없애거나 측정 비율을 올리려는 흔들기를 추가하지 않는다. 최종 판정은 기존 README에 **실제 확인한 시각·내용 / 수정 대상 / 미검증**으로 짧게 남긴다. 자동 게이트 통과와 연출·의미·직접 청취 완료를 한 항목으로 합치지 않는다.

효과음은 [효과음 운영](../../../../resources/sfx/README.md)의 **④·⑤ 청취**에 따라 최종 MP4에서 계획한 큐·대사 명료도·동기·끝 잘림을 확인한다. 메타·봉인 통과를 청취 완료로 처리하지 않으며, 듣지 못한 항목은 미검증으로 남긴다.

## 판정과 수정

사실 오류, 깨진 화면, 정보·음성·자막 누락, 소스와 렌더의 불일치를 구체적인 시각·파일·근거와 함께 보고한다.
**기술 결함 / 근거 있는 연출 개선 / 취향 제안**을 구별한다. 개선은 어느 화면·시각에서 무엇이 약해지고 어떤 변경이 필요한지 설명한다. “AI스럽다”는 말이나 조회수 예측·미학 점수만으로 재제작을 요구하지 않는다. 시각 비교는 같은 발화 구간·표시 크기를 사용한다.

수정은 전부 모아 fix-batch로 처리한다. 워커가 있으면 근거와 범위를 전달하고, 혼자 작업하면 수정 후 별도 검수 단계로 돌아온다.
재심은 변경이 닿는 범위만 확인한다. 폰트·전체 시간축처럼 영향이 전역이면 이유를 밝히고 전체 검사한다.
**D 전에 최종 MP4를 대조한다.** 첫 0~3초는 `hook-check --from`의 `output/review/hook-final.png`(실제 MP4의 정지 표본 — 자막·그림만으로 뜻이 통하는지)를 가장 먼저 열어 판정하고, 연속 재생·청취는 사람이 한다(하지 못했으면 「첫 3초 재생·청취 미검증」으로 D에 넘긴다), 본문의 핵심 변화·장면 경계·마지막 답과 C에서 고친 곳을 확인한다. 인물 실루엣·SVG 팝 오프셋(pitfalls §122)·확대 중 가림은 전후 프레임을 좁혀 본다. 표본 간격은 사건 속도와 위험에 맞추며 전편 0.25초 추출을 기계적으로 반복하지 않는다. 수정이 필요하면 전수 집계 후 재검수한다.
독립 검수를 별도 에이전트(Claude는 `video-director`)에 맡길 때는 **직접 수행·재위임 금지·파일 수정 금지**를 명시한다. 메인이 이미 확인한 항목을 적고, 변경 구간·위험 시각·인물 실루엣처럼 눈으로 판정할 대상에 집중시킨다(00006: 재위임 후 결과 없이 종료 1회). 성긴 타일로 내린 동작 판정(줌·이동 없음 등)은 root 조밀 캡처로 다시 확인한 뒤 채택한다.
유료 음성 재합성은 대본이 바뀐 컷만 하고(`--only`), 변경과 이유를 보고에 적는다 — 묻지 않는다.

렌더 횟수 제한과 열린 수정 묶음을 우회하지 않는다. 같은 오류가 반복되면 더 굽기 전에 원인을 찾는다.
판정은 **통과 / 수정 필요 / 미검증**과 근거로 짧게 쓴다. 별도 DIRECTOR 보고서 파일은 만들지 않는다.

## 인계와 ⑥ — 같은 흐름에서, 멈추지 않고

stage-gate 5가 하드 0이면 **같은 턴에 ⑥으로 간다**(2026-10-22 사용자 지시 「리뷰까지 멈추지 않고」 — 완성 MP4를 올리고 답을 기다리지 않는다 · 여러 편을 한꺼번에 맡길 때만 `video-copy`).
`.claude/skills/review/SKILL.md`를 읽어 현재 영상 내용에 맞는 업로드 문안을 publish.md로 만든다(키워드 조회·유튜브 제목 끝/본문 속 해시태그·형식은 그 스킬이 정본).

```bash
node pipeline/publish-check.mjs <p>
```
