# 카드 게시물 — 영상 하나를 넘겨 보는 카드 세트로

**2026-10-08 사용자 결정:**
- **플랫폼:** 인스타그램 캐러셀 · 스레드 · 유튜브 이미지 게시물. 틱톡·X는 뺀다. 유튜브는 1:1 정사각 판을 따로 짠다(2026-10-09). 스레드·페이스북은 인스타 업로드 화면에서 공유한다 — 스레드 문안을 따로 쓰지 않는다(2026-10-20).
- **장수:** 내용에 맞춰 정한다. 대신 **첫 장이 매우 중요하다** — 다음 장으로 넘기게 만드는 후킹을 첫 장에 넣는다.
- **영상 카드:** 섞지 않는다(섞으면 인스타 음악을 못 붙인다).
- **확인:** 생성을 마친 이미지로 사용자가 확인한다. 업로드는 사용자가 한다.
- **원본 위치:** 카드 원본은 `projects/<p>/cards/`에 둔다.

근거(플랫폼 규격·성과·디자인 사례)는 [07 K01](../../../docs/channel/07-evidence.md), 포스터 위계의 근거는 같은 문서 H03이다.

## 입력 — 이미 있는 것만 쓴다

납품된(⑤ 이후) 영상 프로젝트를 쓴다.
- **사실:** README 「확정 팩트」와 대본 표현 제약 안에서만 쓴다. 새 사실을 조사해 넣지 않는다.
- **첫 장:** README 「첫 3초 비트」 아래 0초 포스터 세 줄(`주제 제목:`·`후킹:`·`키 비주얼:`)이 첫 장이 된다.
- **장마다 한 가지:** `cuts.json`의 컷마다 `headline`·`concept`, 그리고 STORYBOARD의 결과 상태를 쓴다.
- **그림:** `hyperframes/assets/images/`의 생성 이미지, 영상 프레임의 코드 그래픽(지도 경로·아이콘 SVG)을 쓴다. 영상 프레임을 캡처해 쓰지 않는다 — 9:16 자막·움직임 중간 상태가 섞인다. 장에 맞는 그림이 없으면 코드 그래픽으로 그린다. 새 이미지가 꼭 필요하면 video ② 「이미지 생성 요청」 절차(실물 대조 포함)를 그대로 밟는다.
- **글:** 학부모에게 하는 한국어로 대본 문장을 줄여 쓴다(채널04 §3). 카드 캡션 끝에 학원 법정 표시 블록(review 스킬), 마지막 장은 엔딩 카드(채널05 §2-3). 원생 사진은 동의 ✅만.

## 카드 구성 — 장마다 포스터, 세트로는 넘기는 이야기

모든 장은 video SKILL 「최우선」 **0.0초 포스터 행**의 규칙을 따른다.
- 가장 큰 글자가 그 장의 볼 이유이고, `<h1>`에 둔다(대체 텍스트가 이 글자를 그대로 담는다).
- 알아볼 주인공 하나가 그리드 칸에서도 보인다.
- 비교·반전은 그림 안에 둔다.
- **읽을 글:** 첫 장은 두 덩어리(작은 라벨·제목 + 헤드라인)다. 가운데 장은 본문이라 약속을 갚는 **한두 줄 설명**(`.detail` — 그 장의 조건·방법·값, 확정 팩트에서)을 더할 수 있다. 저장할 이유는 이 설명과 마지막 장이 만든다(2026-10-08 「카드에 내용(텍스트)은 안 넣어도 되나」).

| 장 | 역할 | 규칙 |
|---|---|---|
| **1 — 넘기게 만드는 포스터 (가장 공들인다)** | 피드·그리드에서 보이는 유일한 장 | 영상 0초 포스터의 주제 제목·후킹을 그대로 쓰고(`card-render`가 첫 장에서 README 글자를 찾는다), 4:5로 다시 짠다. **무엇이 놀라운지는 보이고 어디·왜·어떻게는 다음 장에 남긴다** — 첫 장에서 답을 다 말하면 넘길 이유가 없다. 오른쪽 아래 넘김 표시(→ 원) 하나는 글이 아닌 장식으로 둔다. 영상 0초와 같은 키 비주얼로 약속을 맞춘다 |
| **2 — 혼자 읽히는 재훅** | 넘기지 않은 사람에게 둘째 장이 다시 보일 수 있다(K01 — 2차 보도라 규칙의 근거로는 쓰지 않고 비용이 없어 지킨다) | 첫 장의 약속을 다른 말로 다시 하고 첫 답을 준다. 이 장만 봐도 주제와 볼 이유가 읽힌다 |
| **3 ~ 끝-1 — 한 장에 한 가지** | 약속을 갚는 본문 | 컷 `headline` 하나가 한 장이다. 그 장의 요점을 가장 크게, 장소·대상 이름을 작은 라벨로, 그 장의 조건·방법·값을 한두 줄 설명으로 쓴다. 같은 틀(로고·라벨·헤드라인·설명 자리)에서 주인공과 구도만 바꾼다. 같은 사진을 연달아 쓰지 않는다 |
| **끝 — 저장할 이유** | 저장·공유 | 다시 볼 만한 요약(목록·지도·전후 값) 한 장. 제목은 그 요약이 답하는 질문이나 결론으로 쓴다(「Which park for which day?」). **「Save this」·「Share this」·「Send this to」 같은 요청 문구는 쓰지 않는다** — Meta가 참여 유도로 강등한다(review §6). 날짜·조건은 확정 팩트 그대로 쓰고, 없는 시한을 만들지 않는다 |

**뻔한 기본값으로 반려되는 것:** 4-designer 「0초 포스터」 반려 목록을 그대로 따르고, 카드에서 더 하는 것은 다음과 같다.
- 첫 장에서 결론을 다 말함.
- 모든 장이 같은 사진·같은 구도.
- 글이 빼곡한 설명판.
- 「Swipe →」 같은 글자로 넘김을 구걸함, 「Save this」·「Share this」 같은 저장·공유 요청.
- 로고·채널 소개로 시작하거나 끝냄.
- 마지막 장이 「Thank you」·「Follow」뿐.

**금지(영상·문안과 같다):** 화면에 출처·URL·확인일·사진 크레딧, 다른 플랫폼 워터마크, 외부 사진·저작자 표시 소재를 넣지 않는다. `card-render`가 출처 패턴(lib/source-ban — 업로드 문안과 같은 목록)과 원격 자산을 막는다(절차 4).

## 절차

1. **재료를 읽는다.** 위 「입력」의 다섯 가지를 본다.
2. **구성을 정한다.** README에 `## 카드` 절을 만들고 표 하나를 둔다: `| 장 | 역할 | 라벨 | 헤드라인(가장 큰 글자) | 주인공·그림 |`. 장수와 고른 이유도 한 줄 적는다. 별도 파일은 만들지 않는다.
3. **카드를 쓴다.** `cards/cards.css`(공용 서체·색·로고·라벨·헤드라인·설명 자리)와 `cards/NN-<이름>.html`을 쓴다(01부터 빈 번호 없이, 1080×1350 정적 HTML). 가장 큰 글자는 `<h1>`, 가운데 장 설명은 `.detail` 한 요소다. 그림은 `../hyperframes/assets/…` 상대 경로로 넣는다. 사진은 주인공이 크게 보이게 자르고(`object-fit` 대신 위치·폭으로), 글자 쪽에 Navy 그라데이션을 깐다. 글자 덩어리는 헤드라인의 실제 줄 수를 보고 아래 덩어리의 자리를 정하고, 한글이 들어가면 `.card`에 `word-break:keep-all`을 둔다(4의 검수가 겹침·단어 중간 줄바꿈을 막는다).
4. **렌더·검수한다.** `node pipeline/card-render.mjs <p>`가 한 번에 렌더와 배치 검수를 한다. 카드는 한 장씩 오래 보여서, 영상에서는 지나가던 넘침·겹침이 그대로 티 난다(2026-10-08 사용자 지시).
   - 하드·경고 항목은 `card-render`가 실행 출력과 `check.png`로 보여 준다(머리 주석이 정본) — 하드면 납품 이미지를 만들지 않는다.
   - 통과하면 `output/cards/NN.jpg`와 `sheet.png`를 쓰고 장마다 `<h1>` 글자를 출력한다.
5. **고친다 — 모아서 한 번에.** `check.png`와 출력 목록의 하드·경고를 전부 모아 아래 표대로 한 번에 고치고 4를 다시 돌린다. 하나 고치고 돌리기를 반복하지 않는다. 경고는 고치거나, 의도면 README 「카드」 표의 그 장 줄에 이유를 적는다. 하드 0이 될 때까지 4·5를 되풀이한다.

   | 검수 결과 | 고치는 법 |
   |---|---|
   | 카드 밖·가장자리 40px | 글자 크기를 줄이거나 `<br>`로 줄을 정한다. 좌우 64px 여백 안에 둔다 |
   | 글자끼리 겹침 | 아래 덩어리의 `top`을 위 덩어리의 실제 줄 수에 맞게 내린다 — 헤드라인 줄 수가 바뀌면 설명 `top`도 같이 옮긴다 |
   | 단어 한가운데 줄바꿈 | 한글은 `cards.css`의 `.card`에 `word-break:keep-all`을 둔다. 영어·숫자는 `<br>`나 글자 크기로 줄을 정한다 |
   | 한두 글자만 남은 줄 | 한 줄에 들어가게 글자 크기를 줄이거나, 의미 단위로 `<br>`를 옮긴다 |
   | 서체가 안 실림 | `cards.css`의 `@font-face` 경로(`../hyperframes/fonts/…`)와 `font-family` 이름을 맞춘다 |
   | 그림 가장자리·그림 속 경계 | 글자를 사물 면(달력 종이·가격표) 안쪽으로 줄여 넣는다 — 글자 둘레(글자 크기의 8%)까지 한 면이어야 하고, 그림 상자 안이라고 통과가 아니다. 그림 밖으로 빼도 된다. 글자가 그림 뒤로 지나가는 구성이면 글자를 그림 아래 층에 둔다 |
   | 대비 3:1 미만 | 글자 쪽 그라데이션을 진하게·넓게 하거나, 글자 색이나 사진 위치를 바꾼다 |
   | 장수 표시 자리 | 오른쪽 위를 비운다 |

6. **눈으로 판정한다.** 검수는 배치만 본다 — 넘길 이유와 위계는 사람이 판정한다. `sheet.png`를 직접 열어 본다.
   - 첫 장이 그리드 칸(맨 아래)에서도 주인공·후킹이 보이고 넘길 이유를 주는가.
   - 둘째 장이 혼자 읽히는가.
   - 장마다 가장 큰 글자가 그 장의 요점인가.
   - 마지막 장에 저장할 이유가 있는가.
   - 첫 장의 글이 두 덩어리인가, 가운데 장의 설명이 그 장의 조건·방법을 확정 팩트로 갚는가(새 사실·다른 장의 내용이 아닌가).

   고칠 것이 나오면 5처럼 모아 한 번에 고치고 4부터 다시 돌린다.
7. **유튜브 판을 짠다.** 4:5 판이 통과한 뒤 같은 장을 `cards/youtube/NN-<이름>.html`로 다시 짠다 — `<html class="sq">`(`cards.css`에 `html.sq,html.sq body,html.sq .card{height:1080px}`), 경로는 `../cards.css`·`../../hyperframes/…`.
   - 장 순서·`<h1>` 글자는 4:5 판 그대로 둔다(대체 텍스트를 같이 쓴다 — 다르면 `card-render`가 경고). 설명은 줄여도 사실은 같게 쓴다.
   - **정사각에 맞춰 다시 디자인한다** — 4:5와 같은 공을 들인다. 사진 장은 전면 사진이다: 주인공을 정사각 안에서 다시 잘라 크게 두고, 글자는 주인공을 피한 쪽(위·아래·옆)에 그쪽 그라데이션과 함께 얹는다. 그래픽 장(지도·입장권)은 그림을 정사각 화면에 꽉 차게 키우고 색면을 더한다. 정리 장도 관련 사진을 어둡게 깔아 맨 바탕으로 두지 않는다. 헤드라인은 `<br>`로 줄을 정하고 4:5만큼 크게(100px 안팎) 쓴다.
   - 🔴 **반려(2026-10-09 사용자 「너무 성의 없이 생성했다 … 배경 깔고 타이포 넣고 그 아래 사진 넣는 건 누가 보겠니」):** Navy 띠 + 글자 + 그 아래 사진 패널로 화면을 나눈 배치, 4:5 화면을 줄이거나 여백을 덧댄 것.
   - `node pipeline/card-render.mjs <p> --youtube` → `output/cards/youtube/`. 4~6처럼 검수·수정·판정한다(프로필 그리드·장수 표시 규칙은 없다).
8. **문안을 쓴다.** `publish.md`에 `## carousel` 절을 review 스킬 「카드 게시물 문안」 형식으로 더한다. 영상 문안과 같은 기준이다 — 캡션 첫 줄(핵심 키워드 + 첫 장의 약속을 릴스와 다른 말로), 인스타 해시태그(첫 해시태그 = 스레드 토픽), 인스타 댓글, 장마다 대체 텍스트. 캐러셀 캡션도 스레드 규격(500자·이모지는 UTF-8 바이트)으로 잰다. 그다음 `node pipeline/publish-check.mjs <p>`를 돌린다(대체 텍스트 ↔ `<h1>`, 캐러셀 첫 줄 ↔ 릴스 첫 줄, 해시태그 수까지 본다).
9. **보고한다.** 두 시트를 보여 주고 카드 경로(`output/cards/01.jpg …` · 유튜브 `output/cards/youtube/01.jpg …`)와 플랫폼별 올리는 법을 알린다. 올리는 법은 review 스킬 「업로드 설정」의 카드 행을 따른다. 사용자가 생성된 이미지로 확인하고 직접 올린다 — 업로드는 하지 않는다.
