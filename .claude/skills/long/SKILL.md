# ABMEN 롱폼 묶음 — Claude /long · Codex $long

**검수된 숏츠의 사실·대사·자산·모션은 재사용하고, 가로 배치·연결·보강의 품질은 묶음에서 확인한다.** 배경만 넓혀도 핵심이 작게 남으면 해당 프레임만 R 재구성한다(08 §4.3). 원본 프로젝트는 고치지 않는다. **0초는 대표 영상의 포스터다** — 조회수가 가장 높은 챕터 1의 포스터 한 장 = 썸네일(`cards/thumbnail.html`: 주연 그림·볼 이유·주제 제목·「+N MORE」)이 0초부터 움직이고 1.5초 안에 주연 그림이 커져 챕터 1이 된다(2026-10-08 사용자 「대표 영상의 포스터 형식으로, 4개로 분할하지 말고」, 08 §3.1). 몽타주 미리보기는 폐지 그대로다(2026-09-26).
정본은 `docs/channel/08-longform.md`다. 이 파일은 실행 순서와 **반복된 실수의 방지책**을 담는다. Claude·Codex 공용 원본이다(Codex는 `.agents/skills/long` 링크로 읽는다). 🔴 이 파일에는 달러 기호 바로 뒤에 숫자를 붙여 쓰지 않는다 — 스킬 인자 자리표시자(달러 기호+번호)로 치환되어 문장이 깨진다(2026-09-27 L1 금액 "3.40달러"의 달러 표기가 사용자 문장으로 바뀌었다). 금액은 "3.40달러"처럼 쓴다. 워커·감독에게 줄 계약은 `pipeline/templates/bundle-worker-brief.md`다.

## 1. 먼저 확인할 것

- **요청 범위:** "구성해 봐"는 ①~② 구성과 ⛳A 제시까지다. 제작(build·렌더)은 사용자가 진행을 말한 뒤에 한다. 문서 정리 요청으로 영상을 만들지 않는다. "진행해"·"N번째 롱폼 진행해"는 08 §2.2에 구성이 이미 있으면 README에 ⛳A 내용을 적고 바로 제작한다.
- **소재 목록:** `node pipeline/hf-bundle.mjs catalog --views`를 실행한다(채널 숏츠 공개 조회수를 한 번 읽는다 — 6시간 캐시, 못 읽으면 조회수 없이). 목록에는 봉인이 일치하는 납품 렌더, 길이, 효과음 밀도, 자막 효과, 이미 쓰인 묶음이 나온다. `묶음 불가`인 편(작업 중·렌더 없음)은 넣지 않는다.
- **이미 계획된 묶음:** 08 §2.2의 두 표 — L1~L4 원안(납품됨 · 00028·00029·00026·00036)과 L5~L14 재배정(2026-10-08). **L5·L6은 재배정 표가 현행이다**(원안 행은 취소선). 사용자가 "L3"·"두 번째 롱폼"처럼 지목하면 그 구성을 그대로 쓰되 catalog로 현재 상태를 다시 확인한다. 번호↔L은 08 §2.2 표의 프로젝트 열, 진행 상태는 그 README가 정본이다(폴더: `ls projects | grep -- -long-`).
- **한 편은 한 주제 묶음에만** 넣는다. 전편 모음만 예외다(08 §2.2).
- **챕터 수:** 3~5편. 3편 미만이면 YouTube 챕터가 표시되지 않는다(각 10초 이상, 첫 줄 0:00). 10편 이상은 도구가 시험되지 않았다(08 §11).
- **승인 렌더:** 원본 README의 최종 승인본을 쓴다. 가장 새 `render-hf-vN`을 승인본으로 가정하지 않는다(08 §2.1).
- **이전 묶음의 미결 결정**(음량·원본 효과음·CC·AI 표시)에 사용자가 답하지 않고 다음 묶음으로 넘어가면, 알린 기본값을 그 README에 적고 진행한다.

## 2. 소재를 정하는 두 방식

**A. 사용자가 정해 준다** — 번호 목록이나 묶음 이름이 주어진다.
- 순서·챕터 1은 08 §2.4 원칙으로 내가 정하고 이유를 한 줄 적는다.
- 길이가 3:00~4:00을 벗어나면 넣고 뺄 후보를 제안한다.

**B. 키워드만 준다** — 예: "음식", "밤의 서울", "공짜".
1. catalog의 제목·훅에서 키워드와 맞는 편을 고른다. 판단이 애매하면 그 편 README의 첫 절(약속)만 읽는다. 모든 README를 통째로 읽지 않는다.
2. **이야기 연결을 찾는다** — `node pipeline/hf-bundle.mjs catalog --headlines`로 컷 제목의 연도·사건·대상을 보고, 시간순이나 원인→결과로 이어지는 순서를 만든다(08 §2.5, 예: L6 1394 → 1395 → 전쟁 → 재건).
3. **원본 합 약 161~222초**가 되게 3~5편을 고른다. 이렇게 하면 0초 포스터 1.5 + 원본 + 노선 전환 약 1.9~2.4×(n−1)(`gap_s` 1.9를 0.5초 격자에 맞춘 값, 08 §6) + 완주·정리 약 11.5가 3~4분이 된다(L2: 원본 210.5 → 3:51). 모자라면 억지로 채우지 않는다. 어떤 숏츠가 더 있으면 되는지 제안한다(새 숏츠는 /video).
4. 이야기가 확실히 나은 구성이 4분을 넘으면 **이야기 우선안과 길이 준수안을 나란히** 낸다. 초과 여부는 사용자가 정한다.
5. 약속 한 줄과 챕터 순서를 정한다. 🔴 **챕터 1 = 고른 편 중 공개 조회수가 가장 높은 편**(2026-10-08 사용자 「첫번째가 조회수 잘 나오는 걸로」) — 0초 포스터가 그 편의 포스터다. 각 편의 조회수를 `chapters[].views`에 적는다(`plan`이 확인). 이야기 순서가 확실히 나아 바꾸면 README에 근거. ⛳A로 제시한다.

⛳A 제시 형식(대화에 한 번에):

| # | 원본 | 길이 | 라벨(승인 영어 제목) | 역할 |
|---|---|---:|---|---|

아래 줄을 함께 적는다.
- 약속·제목 후보 3개 · 썸네일(= 0초 포스터, 챕터 1 한 장): 볼 이유(가장 큰 글자 — 챕터 1의 놀라운 값·반전)·주제 제목·「+N MORE」, 08 §8.1
- 챕터 라벨. 필요하면 다리 문구를 쓴다(새 영어, 음성 없음)
- 예상 길이
- §7.4 보강 대상(catalog의 `효과음↓`·`자막정적`)과 읽기 멈춤 호흡 대상(원본 정지가 많은 초기 숏츠, 08 §4.6)
- 노선 전환: 정거장 이름·아이콘(`resources/icons/`에 있는 이름만), 머리글(`route_kicker`)·완주 제목(`finale_title`) — 약속에 맞는 새 영어(08 §6)
- 결정할 것(자막 A/B, 연결 멘트 유료 여부)

## 3. 제작 절차 — 단계별 체크리스트 (08 §10)

```bash
pipeline/new.sh <슬러그> --bundle                       # cuts.json 명세 + README 양식 → projects/NNNNN-long-<슬러그>(롱폼 폴더는 번호 뒤 long, 2026-10-08)
node pipeline/hf-bundle.mjs <p> plan                  # 봉인·길이·음량·YouTube 챕터 (cuts.json 시간축)
node pipeline/hf-bundle.mjs <p> build                 # 조립만 — 템플릿·라벨·완주·정리 설정을 바꿨으면 해당 compositions/bundle 파일을 지우고 다시(실수 13)
node pipeline/hf-bundle.mjs <p> sheet                 # 조립 + 전 프레임 3시점·전환·정리 시트 → B 분류·자막 띠 확인
node pipeline/hf-bundle.mjs <p> snap <폴더> <t1,t2,…>  # 조립 + 원하는 시각 스냅샷 (워커·감독 공용)
node pipeline/hf-bundle.mjs <p> thumb frames <poster_s>             # ④ 썸네일 = 0초 포스터의 주연 그림 — 챕터 1 첫 화면 스냅샷 → cards/assets/frame-<초>.jpg
node pipeline/hf-bundle.mjs <p> thumb check           # ④ cards/thumbnail.html 촬영+검사 → 통과해야 output/thumbnail.jpg, 다음 조립에 0초 포스터 (08 §8.1)
node pipeline/hf-bundle.mjs <p> verify [--chapter N]  # 조립 + 무대 = 원본(SSIM, 드리프트 역산) + 좌우 경계 판정
node pipeline/review-sheet.mjs <p>                    # ⛳B·C 가로 검수 시트(챕터별, 사용자에게 보일 때)
node pipeline/hf-bundle.mjs <p> loudness [--apply] [--keep <mp4>]  # 조립 + 1fps 측정 렌더(납품 아님) → 챕터 음량·배율·피크 지점
pipeline/hf-render.sh <p>                             # 납품 렌더 1회 (0초 포스터는 렌더 전에 들어가 있다 — 본편 = 최종)
pipeline/render-gate.sh <p> <파일>                    # 가로면 verify --video(규격·챕터 음량 차이·무대 = 원본 MP4)
node pipeline/hf-export.mjs <p>                       # SRT·타임라인·output/chapters.txt
node pipeline/stage-gate.mjs <p> 5                    # 하드 0
node pipeline/publish-check.mjs <p>                   # 문안 실패 0
```
`build`·`verify`(무대)·`loudness`·`snap`·`sheet`는 묶음 잠금 안에서 돈다. 워커 여럿이 동시에 불러도 된다. **렌더 중에는 조립을 거부한다** — 렌더 도중 소스가 바뀌면 봉인 이탈로 렌더가 버려진다.

### ① 명세 → plan
- [ ] `cuts.json`: `promise`·`captions: "burn"`·`gap_s: 1.9`·`poster_s: 1.5`(0초 포스터 — 템플릿에 있다)·챕터마다 `project`·`render`(README 최종 승인본)·`label`(승인 영어 제목 — 슬러그면 `publish.md` 첫 줄)·`stop`·`icon`, 묶음의 `route_kicker`·`finale_title`
- [ ] `plan` → 봉인 n/n 일치, 길이 3~4분(초과는 ⛳A에서 사용자가 정한 경우만)
- [ ] 팩트는 다시 확인하지 않는다(08 §2.1)
- [ ] **첫 `build` 전에** 머리글·완주 제목·정리 배치 같은 템플릿 결정을 끝낸다(실수 13)

### ② ⛳A — README 약속·챕터·제목·썸네일(= 0초 포스터) 볼 이유 (계획된 묶음은 README에 적고 진행)

### ④ 조립·가로 확장·보강
- [ ] `sheet` → B / B 확장 / 대기 요소 / R 분류. **배경의 연속과 정보의 가로 가독성을 별도로** 본다. 320×180에서 주연·값·비교 관계가 작게 뭉치면 그 프레임만 R로 재배치한다(08 §4.3). R은 SSIM 대상에서 빠지므로 원본과 사실·발화·동작 의미를 직접 대조한다. 챕터마다 자막 띠의 문구도 확인한다
- [ ] 좌상단 로고가 넓힌 밝은 배경에서도 읽히는지(실수 15)
- [ ] 챕터별 워커(`video-worker`)에게 `bundle-worker-brief.md` A절로 위임(범위: `override/chNN/` + 효과음 JSON). 띄운 사실을 대화로 알린다
- [ ] 워커 효과음 JSON을 합쳐 `chapters[].sfx`에 넣는다. 원본 큐가 숫자를 가리면 `audio_edit`
- [ ] `node pipeline/motion-audit.mjs <원본.mp4> --json`으로 읽기 멈춤 후보를 찾고 실제 구간을 본다. 잦은 끊김이 확인된 초기 챕터는 `chapters[].drift: 0.03`(08 §4.6)을 시작값으로 시험한다. 정지 수만으로 자동 적용하거나 줌을 의미 있는 설명 동작의 대체품으로 쓰지 않는다. 이어지는 요소·읽을 글자가 튀지 않는지 `snap`으로 확인
- [ ] **썸네일 = 0초 포스터 — 대표 영상(챕터 1) 한 편의 포스터. 절차·수치는 08 §8.1**(2026-10-08 사용자: "4개로 분할해서 넣지 말고 4개 중 대표 영상으로 … 그 영상의 포스터 형식으로 … 3개 더 있다 정도"). B 확장을 마친 뒤, `verify` 전에 한다
  - [ ] `thumb frames <poster_s>` → `cards/assets/frame-<초>.jpg`(챕터 1 첫 화면 조립본 스냅샷)
  - [ ] `pipeline/templates/thumbnail-long.html` → `cards/thumbnail.html`, `TODO-`를 전부 채운다. **숏츠 0초 포스터와 같은 문법**(2026-10-08 「video 스킬 포스터처럼 기교 빼고」): 그림 #t1이 화면 가득(16:9 상자, 주연 크게, 글자 자리인 하늘·벽을 남긴다 — 모자라면 상자를 프레임 밖으로 넓히고 #t1 바탕색을 그 그림 색으로), 그 위 빈 곳에 Hahmlet 제목 + Inter 후킹 줄(라임 한 단어) + 여지가 있으면 「+N MORE」. 볼 이유 덩어리에 `class="reason"`(가장 큰 글자). 글자를 주연·밝은 사물 위에 얹지 않는다
  - [ ] `thumb check` 실패 0·위계 경고 0(실패가 있으면 `output/thumbnail.jpg`를 쓰지 않는다) → tmp의 `check-phone.png`(168×94까지)로 주연이 무엇인지·볼 이유가 읽히는지, 넓힌 쪽에 잘린 도형·이음매가 없는지 **눈으로** 본다(볼 이유의 힘은 검사기가 모른다)
  - [ ] 네 칸 조합판·한 장면판은 YouTube 썸네일 A/B 후보로만(`--alt`) — 0초 포스터는 기본 `cards/thumbnail.html`만 쓴다
- [ ] 포스터·전환·라벨·완주·정리는 스냅샷으로 본다 — `sheet` 첫 줄 = 포스터(0초·커지기 직전·커지는 중). 전환·라벨·정리 설정을 바꿨으면 해당 파일을 지우고 다시 조립(실수 13). `poster.html`은 썸네일에서 매번 다시 만든다
- [ ] `verify` 전 챕터 ✅ · 0초 포스터 ✅(자리표시 아님 · 0초 = `output/thumbnail.jpg` · #t1 = 챕터 1 첫 화면) (드리프트가 있으면 역산해 비교한다. 줌아웃 프레임은 `△ 가장자리 60px만 다름`이 뜰 수 있다 — 안쪽 x60~1020이 같으면 통과, 기준값은 낮추지 않는다) · `hf-cli lint` 오류 0(경고 `duplicate_audio_track`은 원본 음성 클립 겹침 — 원본 그대로)
- [ ] `node pipeline/stage-gate.mjs <p> 4` 하드 0 — 0초 포스터 자리표시·묶음 전용 파일·챕터 프레임/오디오 수(숏츠용 0~3초 재생 경고는 묶음에 뜨지 않는다)
- [ ] **⛳B·C는 ④ 끝에 한 번** — 포스터·전환·정리 스냅샷과 챕터별 검수 시트(`review-sheet`)를 함께 보인다. 일괄 진행 지시("멈추지 말고")가 있으면 보고만 하고 ⑤로 간다

### ⑤ 렌더 전 게이트 → 렌더 1회 → 납품 검사
- [ ] `loudness` → 챕터 차이 ≤ 2 LU(목표 1 LU 안팎). 배율은 줄이기만(`--apply`는 가장 조용한 챕터 +0.5 LU 위를 내린다). 피크 지점이 묶음이 넣은 클릭이면 volume을 낮춘다(실수 6)
- [ ] 측정 렌더(`--keep`)의 첫 2초 — 0초 포스터는 배경 곡(−24 LUFS)뿐이다. 1.0초 whoosh와 1.5초 챕터 1 시작에서 소리가 튀지 않는지 잰다(`loudness`는 챕터만 잰다): `ffmpeg -v info -i <keep.mp4> -t 2.5 -af ebur128=peak=true -f null - 2>&1 | grep -E 'ebur128.* t:'` → 0.1초마다 M(순간 음량)·FTPK(트루피크). 1.0·1.5초 전후 M이 배경 곡보다 10 LU 넘게 뛰거나 FTPK가 −1 dBFS를 넘으면 큐 volume을 낮춘다(실수 6)
- [ ] **렌더 전 감독**(`bundle-worker-brief.md` B절) — 시트·측정 렌더(`--keep`)·워커 이탈 목록을 넘긴다
- [ ] 감독 지적 **전부**를 fix-batch 한 장부로 열고 유형·전수 수를 적은 뒤 고친다 → 고친 곳만 `snap`·`verify`·(소리가 바뀌었으면) `loudness` → 닫는다. 장부를 연 뒤 새로 찾아 고친 것은 README에 적는다
- [ ] `pipeline/hf-render.sh <p>` 1회(상한 3회) → `render-gate`(가로면 `verify --video`) → `hf-export` → `stage-gate 5` 하드 0
- [ ] 납품 MP4에서 직접 뽑은 프레임: **첫 3초를 휴대폰 크기(320×180)로**(0초 포스터 → 커지는 중 → 챕터 1 훅), 전환·고친 곳·정리 화면. 훅 소리가 납품 믹스에 남았는지 대역 측정
- [ ] render-gate의 정지 구간·이음매 🔴는 원본 숏츠 MP4와 대조한다(원본의 읽기 멈춤·색면 하드컷이면 결함이 아니다 — 그래도 수치를 보고한다)
- [ ] README 「현재 상태」(⛳D 대기·렌더 횟수·수치·사용자가 정할 것)

### ⑥ 문안
- [ ] `publish.md` 유튜브 롱폼 한 곳 — /review 지시서(맡기면 `video-copy`). 첫 줄 제목 ≤ 100자(해시태그 1~3개 포함), 챕터 줄은 `output/chapters.txt`와 같게, 본문 문장 속 해시태그 1~2개, 챕터별 수치는 각 숏츠의 승인된 업로드 문안에서 그대로 옮긴다
- [ ] `publish-check` 실패 0
- [ ] 업로드 썸네일은 `output/cover.jpg`다 — `hf-export`가 납품 MP4의 0초(= ④ `thumb check`로 맞춘 포스터)에서 뽑는다(1920×1080·2MB 미만, 없으면 `stage-gate 5` 하드). 사용자에게 연다(`open output/cover.jpg`)
- [ ] Related video 연결 목록(챕터 1 숏츠부터)

단계별 할 일·컨펌은 위 체크리스트 순서 그대로다(①명세·plan → ②⛳A → ④build·sheet·B 확장·보강·썸네일·verify → ⑤측정 렌더·감독·렌더 1회·게이트·export ⛳D → ⑥문안).

## 4. 수정 요청이 왔을 때 (⛳D 뒤)

- 지적을 받으면 바로 손대지 않는다. **원인부터 가른다** — 렌더 결함(같은 프레임 반복·끊김)인지, 원본 숏츠의 설계(읽기 멈춤·하드컷)인지, 묶음이 더한 것(전환·확장·보강)인지. L2 "잠깐씩 멈추는 곳"은 motion-audit를 원본 MP4와 대조해 49곳 모두 원본의 읽기 멈춤임을 확인하고 드리프트로 풀었다.
- `fix-batch open`에 사용자 지적을 **전부** 적고, 유형으로 일반화해 전수 수를 적는다 → 전부 고친다 → `verify`·스냅샷 → 닫는다 → 렌더(상한 3회).
- 사용자가 "과하지 않게"라고 하면 강도를 낮추되 방식은 전체에 일관되게 쓴다(한두 곳만 다르게 하지 않는다).
- 원본 숏츠의 편집 리듬(색면 하드컷 등)은 사용자가 지적하지 않았으면 바꾸지 않는다.

## 5. 품질과 리소스 — 2026-09-26 사용자 지시

- **차이만 검사한다.** 원본 챕터는 숏츠에서 이미 통과했다. 렌더 전 `verify`(스냅샷)가 선별하고, 렌더 뒤 `verify --video`(렌더 MP4 = 원본 MP4)가 최종 판정한다. 사람이 보는 것:
  - 좌우 끝까지 한 장면인가, 가로 표시 크기에서 핵심 대상·값이 읽히는가(세로 기둥·드러난 대기 요소 없음)
  - 0초 포스터(썸네일과 같은가 · 볼 이유가 가장 큰가 · 챕터 1로 끊김 없이 열리는가)·전환·라벨
  - 정리 화면: 오른쪽 엔드스크린 자리를 유지하면서 왼쪽의 결론·대표 대상이 읽히는가. 원본 글자가 뭉개진 작은 썸네일 모음으로 요약을 대신하지 않는다
  - §7.4 보강분(자막 강조·효과음)
  - 챕터 음량 차이
- **지적은 전수 집계 → 한 번에 수정 → 한 번 재검수.** `node pipeline/fix-batch.mjs open <p> …`. 한 건씩 굽지 않는다.
- **렌더 1회 원칙.** 상한 3회. 무대·여백·소리 문제는 렌더 전 `sheet`·`verify`·`loudness`·감독에서 모두 잡는다.
- **스튜디오는 사용자가 요청할 때만** 연다. 내 확인은 스냅샷·시트·게이트로 한다.
- **컨텍스트:** 새 묶음 제작은 새 세션에서 시작한다. 이 스킬과 08 문서, 프로젝트 README만으로 이어 할 수 있다. 위임은 범위가 명확한 일에만 한다. 대상은 챕터별 B 확장, §7.4 보강, R 재구성 프레임, 전환·정리 디자인이며 `pipeline/templates/bundle-worker-brief.md`(묶음 전용)와 `pipeline/templates/worker-brief.md`(공통) 계약을 쓴다. 워커를 여럿 띄우면 대화로 알리고, 결과를 기다리는 동안 내 몫(전환·정리 확인·README·문안 준비)을 한다.
- **청취:** 현재 세션의 실제 청취 가능 여부로 판단한다. 듣지 못했으면 신호 측정(대역·음량·피크)과 청감 미검증을 구분해 보고하며 측정값을 청취 완료로 쓰지 않는다.

## 6. 하지 않는 것

- 원본 숏츠 프로젝트를 고치지 않는다. 보강은 묶음의 `hyperframes/override/`와 `bundle.chapters[].sfx`·`audio_edit`·`drift`에만 한다.
- 세로 MP4를 가로 캔버스에 붙이지 않는다. 색면 칼럼(C)으로 세로 기둥을 남기지 않는다(08 §4.3). 0초에 로고 인트로·몽타주 미리보기를 넣지 않는다 — 0초는 대표 영상(챕터 1) 포스터 한 장 = 썸네일이다(08 §3.1·§5). 네 칸으로 나누지 않는다.
- 유료 음성(연결 멘트)을 승인 없이 만들지 않는다.
- 봉인이 맞지 않는 원본을 묶지 않는다(`build`가 거부한다). 음량을 올려서 맞추지 않는다(08 §7.2 실측).
- 전체 음량을 고정하려고 원본 숏츠의 효과음 균형을 바꾸지 않는다(§147 — AAC 흔들림 때문에 고정되지도 않는다).
- 포장(썸네일·제목·챕터 라벨)에 사용자가 뺀 요소(**북한**)나 묶음 약속에서 벗어난 요소를 쓰지 않는다. 본편은 숏츠 그대로 둔다(08 §2.5).
- 원본 효과음 중 신규 사용 중단 파일(VideoEditingSFX)을 소급해 바꾸지 않는다 — 사용자가 정할 때만 `audio_edit`로 묶음에서 바꾼다. 새로 넣는 효과음은 확인된 CC0만(`build`가 거부한다).

## 7. 환경·도구 메모

- 4분 가로 납품 렌더는 저메모리 모드로 약 16분, 측정 렌더(`loudness`)는 약 1.5분, `sheet`·`snap`·`verify`는 수십 초~1분.
- HyperFrames 스냅샷에 요청하지 않은 `at-224.07s` 같은 칸이 섞일 수 있다(도구가 찍는 것). 요청한 시각의 파일만 쓴다.
- zsh에서는 `set -- $var`가 단어를 나누지 않는다(`${=var}`). `timeout` 명령이 없다.
- `thumb check`·`zone-check.sh`는 python3 PIL을 쓴다 — 시스템 python3에 PIL이 없는 기기는 `~/.venvs/abm-whisper/bin`을 PATH 앞에 둔다(커밋 b7bf86d). Chrome은 `/Applications/Google Chrome.app`.
- `snap`은 HyperFrames 스냅샷이라 30fps 프레임 격자다 — `48.2333`처럼 소수 넷째 자리 시각은 3자리로 접혀 `48.2`와 같은 프레임이 나온다. 퇴장·경계 확인에는 다음 프레임 시각(`…+0.0333`의 3자리 반올림)이나 소스 계산을 쓴다.
- 감독·워커가 API 오류로 중단되면(`idleReason: failed`) 네트워크를 확인하고 `SendMessage`로 같은 이름을 깨우면 이어서 한다(L4 감독이 그렇게 마쳤다).
- `thumb frames`·`snap`·`sheet`·`verify`는 조립(`build`)부터 한다. 납품된 옛 묶음(L1~L4)에서 부르면 그 뒤 바뀐 공용 코드(브랜드 CSS 등)로 `index.html`이 다시 쓰여 렌더 봉인과 어긋난다 — 수정 요청으로 다시 렌더할 때만 부른다. 0초 포스터가 없는 묶음의 조립 결과는 이번 변경 전과 같다(2026-10-08 L4 사본 대조).
- 스크래치 파일은 세션 스크래치패드에 둔다. 저장소에 중간 산출물을 남기지 않는다.
